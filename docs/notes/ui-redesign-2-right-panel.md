# 界面改版 阶段 2：右侧面板（2026-09-28）

spec §4.2 / §5.6 / `mock-session.png` 右侧。「显示工作台工具」打开时右侧面板就是原来的停靠面板（每个面板都是可关、可拖进分屏的图标标签 + 最小化成图标栏），下面说的是默认界面。

- **`PANELS.tier`**：`core` = 四个固定标签 审阅（id 仍是 `files`：`panel.files` / Ctrl+Shift+2、老布局里的 `files` 标签都直接变成审阅）· 文件（`explorer`）· 终端 · 任务（`CORE_PANELS` 定顺序）；`extra` = 右侧面板「更多」（＋）菜单里的目标 / 编排 / 用量 / 详情 / Issue 与 PR（`board`，新面板，原「看板」视图），打开成带 × 的临时标签；`workbench` = 总览 / 记忆 / 配置中心 / Android，只从命令面板 / 快捷键打开（也是临时标签），「显示工作台工具」后在图标栏。
- **`dockView(dock, {workbench, inspect})`**（纯函数，`model/right-panel.test.ts`）：`mounted` = `dock.tabs` + 被请求的「详情」，面板体只按它渲染、只用 `hidden` 切换——切标签、隐藏面板、开关「显示工作台工具」都不卸载（ui-smoke 用同一个 xterm 元素上的标记验证）；`tabs` 在默认界面是四个固定标签（没打开过的也显示，点一下 `dock.show` 才挂载）+ 其它已挂载面板。固定标签没有 ×，它的开关只 `hide`；临时标签的 × 走 `dock.close`（以前 × 走 `dock.toggle`，点不在前面的标签的 × 会把它切到前面而不是关掉）。默认界面 `dock.close {workbench:false}` 关掉前面的临时标签先落到下一个临时标签；关掉最后一个时面板不收起，落回**最后在前面的那个固定标签**（`Dock.lastCore`：`layoutReducer` 每次动作后只要前面是固定标签就记下，点标签 / 开关 / show / close 都算；它已经被关掉（工作台模式能关）就不重新挂——重开终端是一个新 shell——退回第一个挂着的固定标签，一个都没打开过就挂上审阅）。`sanitizeLayout` 丢掉不认识的面板 id，`lastCore` 只留固定标签。
- **新布局一个面板都不挂**（`initialLayout().dock.tabs = []`，审查 I1）：挂着的隐藏审阅也会对当前对话的仓库发 `git.watch`（服务端 chokidar + 每 5 分钟后台 `git fetch --prune`，永不取消），而桌面版每次启动都是新布局。第一次打开（会话头按钮 / Ctrl+J / 图标栏）走 `dock.toggle` 命令，没有标签就 `dock.show defaultDockPanel(workbench)`（默认界面是审阅，工作台模式是任务）；`dock.minimize` 同理。工具行「详情」→ `App` 的 effect 调 `showPanel('inspector')`：详情已经是标签但在别的标签后面时也会被带到前面（以前只把面板打开，点了没反应）。**手机上**（阶段 7 起右侧面板是底部抽屉）：工具行不画「详情」按钮（行本身点开就是同样的输入和结果）；步骤视图里的一行照样进抽屉里的详情；文件（附件芯片、Alt+点击路径）像普通点击路径一样原地开文档标签（整屏比抽屉好读），处理完就清掉 `inspect`。
- **审阅 `workbench/ReviewView.tsx`**（合并了原来的「文件改动」面板 `FilesPanel`（已删）和 `GitView` 的 status / diff / 暂存 / 提交；纯逻辑在 `review-model.ts` + 测试）：范围菜单 未提交的改动（仓库里的默认）/ 已暂存 / 本次对话改动（`files.changed`，不在仓库里时的默认）/ 最近 20 次提交里的某一次（`git.show` 按文件切开，`splitUnifiedByFile`）；status 回来之前范围写「读取中…」，不先显示一个猜的范围再跳。**文件行的路径**：仓库里的文件是仓库相对路径；本次对话范围里不在仓库里（或根本没有仓库）的文件按**对话目录**显示相对路径（`reviewRows(…, {cwd})`，统一打磨 P4；以前是一长串绝对路径、文件名被截掉），只有在对话目录之外的才显示全路径；全路径一直在行的 tooltip 里；灰色目录部分先省略，文件名（`.p .f`）不缩（改动文件卡同样）；有目录时目录至少留 2.4ch——`text-overflow` 从不省略第一个字符，挤到 1 个字符宽时只剩一个灰字母、没有省略号，窄分屏里 `src/menu.ts` 读成了 `smenu.ts`。逐文件折叠 diff（`DiffView`，头部藏掉、代码不折行横向滚动、行号 sticky，上下 / 并排跟 `ui.diffMode`，在 ··· 里切）；全部还原（只在「未提交的改动」）/ 全部暂存（已暂存范围是全部取消暂存）、每个文件的 暂存 / 取消暂存 / 还原 / 在编辑器打开；底部提交说明（textarea，Enter 换行、Ctrl+Enter 提交，同 Git 视图）+ 提交。分支 / 拉推 / 历史 / amend / 暂存区快照（stash）/ 独立副本（worktree）在 ··· →「Git」二级视图（`GitView`，第一次打开后常驻；界面文字不写 stash / worktree，放 tooltip）。`GitView({cwd, visible})`：看不见时（审阅的差异列表在前、右侧面板隐藏、被挡住的窗格）不跑 git，`git.changed` 只记 stale，下次显示再刷新；`git.watch` 在第一次显示时才发。切换对话时审阅把 Git 二级视图整个卸掉（`gitMounted` 清掉），不在后台对新仓库重新挂载（以前每切一次对话就是 4 个 git 进程 + 一次 watch）。
  - **每个文件的 diff 怎么取**（`diffRequest`）：只改了工作区或只暂存了 → 一次 `git.diff`（一个 git 进程）；既暂存又改了 → `files.diff`（HEAD 对工作区）；本次对话范围一律 `files.diff`。前 8 个文件先取（为了行尾的 +N −M），其余展开时才取，默认展开前 3 个，最多列 300 个文件。
  - **只在看得见时问 git**（`visible`）：`git.watch` 在这个仓库**第一次显示**时才发（每个实例每个 cwd 一次），只是挂着不发；看不见时来的 `git.changed` / `fs.changed` / 会话轮次只记 stale，下次显示再刷新；刷新 `coalesce(600, 3000)`。会话里的改动用「编辑类工具完成数 + lastResult」签名触发（只在可见时 walk）。每个文件的请求带序号，旧请求 / 别的会话的回包不会覆盖新的。窗格里的面板标签（工作台模式拖进分屏的审阅）也按 `Tile` 的 `visible` 走，被挡住就不跑 git。
  - **还原就是 `checkout HEAD` + 删新文件**（`fs.rm`，不进回收站），整个文件回到上一次提交，不管改动是谁做的。所以「本次对话改动」范围**不给全部还原**，只有单文件还原；确认框由 `discardConfirm()` 生成：批量列出文件（最多 8 个 +「…等 N 个文件」，`dlg` 新增 `items`），写明「不只是这个对话做的改动」，**只在真有的时候**写「包括已暂存的改动（N 个文件有）」「新建的文件会被永久删除（不进回收站）：N 个」；单文件按状态说新文件会被永久删除 / 已暂存的也丢 / 本次对话范围里别人的改动也丢。`dlg.confirm({focusCancel})` 让「取消」拿焦点，点完还原再按回车不会直接执行；每个对话框有自己的 `key`（`Pending.id`），排在别的对话框后面的也是重新挂载、`autoFocus` 生效（否则按钮 DOM 被复用，焦点停在上一个对话框点过的「确定」上）。
  - **暂存 / 取消暂存 / 还原的路径走 stdin**（`GitService.runPaths`：`--literal-pathspecs … --pathspec-from-file=- --pathspec-file-nul`，**git ≥ 2.25**）：「全部暂存并提交」给的是逐个文件的列表，1400 个文件放命令行在 Windows 上 `spawn ENAMETOOLONG`（32767 字符上限）；`--literal-pathspecs` 让 `glob[1].txt` 这种文件名按字面匹配。**老 git 退回命令行**（Ubuntu 18.04 是 2.17、Debian 10 是 2.20，远端 / SSH 那台机器常是这种）：`pathspecFromFile()` 按进程只问一次 `git --version`（模块级缓存，所有 `GitService` 共用；`resetGitVersionCache()` 给测试用），低于 2.25 就 `-- <paths>` 按 `argvBatches()` 分批（每批路径 + 引号 + 空格 ≤ `ARGV_PATHS_BUDGET` 24 000 字符）；版本号说支持、git 却报 `unknown option` / `pathspec-from-file` 时同样退回，并从此记住。判断看 `GitCommandError.stderr`（完整输出）——`info.message` 只留最后几行，git 在错误后面还会打一大段 usage。`git/service.test.ts`：1400 个长路径（拼起来超过 32767）走 stdin、每次调用的 argv 都很短；桩成 `git version 2.20.1` 时同样 1400 个文件分批走命令行、每批不超预算、不带 `--pathspec-from-file`、`--version` 整个进程只问一次；桩成「拒绝这个选项」时退回一次并记住，其它错误（index.lock）照常抛给调用方。
  - **全部还原 / 全部暂存不碰冲突文件**（暂存 = 标记冲突已解决，checkout = 丢掉一边），只加到暂存区的新文件没有可还原的版本，已暂存的重命名 / 复制也不给还原（`checkout HEAD -- 新路径` 找不到，服务端退回的 `checkout --` 什么都不做），都留给取消暂存（`bulkTargets`）。
  - **提交**（`commitPlan()` 返回 `{kind, stage, untracked, conflicts, staged}`）：有冲突文件 → 不提供提交，底部提示「有 N 个冲突文件：先在 Git 视图里解决」+ 打开 Git 视图（`git add` 会把带 `<<<<<<<` 的文件标成已解决，git 本身也拒绝带未合并文件的提交）；没有已暂存的改动 → 问「把 N 个文件的改动暂存并提交？」（`stageAllConfirm()`，写明其中几个是没提交过的新文件），暂存的是 `bulkTargets` 的 stage 集合，**不是** `git add -A`。
  - 范围菜单的提交列表要在 effect 里按 `[菜单开着, root]` 取：点开菜单时 status 可能还没回来（root 为空），在点击回调里取就永远是「读取中…」（踩过）。
- **文件 `workbench/FilesView.tsx`**：顶部「文件 · 搜索」切换，`FileTree` 和 `SearchView` 都常驻（`hidden`），搜索第一次切过去才挂载（它会自动聚焦）；树上方是「本对话生成的文件」分组（原「产物」视图，`workbench/Artifacts.tsx`）：有才显示，但从 ··· / 命令面板点「生成的文件」时 0 个也显示分组和空状态（否则像是点了没反应）。`useGitStatus` 挪到了 `workbench/git-status.ts`（只在文件树可见时跑）。
  - **文件预览在文件标签里**（2026-11-01，用户要求，照官方桌面版）：点文件树 / 本对话的文件 / 生成的文件 / 搜索结果 / 对话里的文件链接和工具卡路径都走 `previewFile(path, line?)`（`right-panel.ts`），不再在主区开 doc 标签：右侧面板切到「文件」，左边是预览（每个文件一个小标签，`DocTile` 原样嵌进去，最多挂 8 个、都只 `hidden`），右边是文件树一列；预览栏右上的按钮隐藏 / 显示文件树（`ui.filesTreeHidden`，存 meta.json）。第一次打开预览时面板不到 760px 就加宽到 760。关掉最后一个预览回到整列文件树；未保存的预览关之前 `dlg.confirm`。手机上 `previewFile` 仍原地开 doc 标签。只在右侧面板那份（`inDock`）显示预览。右键菜单「打开」= 预览，「在标签页打开」/「在右侧分屏打开」还是主区；审阅 / Git 的「在编辑器打开」、设置里编辑技能也还是主区标签。
- **任务**：会话的后台任务 + 最近一次 TodoWrite 计划（`TodoBody`）+ 子代理 / 后台调用树；定时任务列表只在「显示工作台工具」时留在顶上，默认界面底部是一行「定时任务 · N … 在「自动化」里 ›」（`SchedulesLink`），有没有打开对话都一样；`openSchedules()`（侧栏「自动化」、这一行之类的入口）从阶段 7 起就是 `openAutomation('schedules')`（桌面和手机一样，永远返回 true，签名保留）。
- **打开请求**：`workbench/right-panel.ts` 是一个独立的小 zustand（`useRightPanel`：`review` / `explorer` 请求带递增的 `n`；`reviewCount` 给「审阅 3」的数字）。**对外接口，签名保持稳定**：`showPanel(panel)`（手机上就是底部抽屉，永远返回 true）、`openReview({scope, rev, path, git})`、`openExplorer(mode)`、`openSchedules(): boolean`、`openSessionView(view, at?)`；阶段 5 的「改动文件卡」点文件用 `openReview({ scope: 'session', path })`。**只有右侧面板里那一份审阅 / 文件接请求、发数字**（`PanelBody host='dock'` → `inDock`；工作台模式拖进窗格的那份是 `host='tile'`），模块级 `appliedIntent` 保证每个请求只用一次（关掉再打开不会重放旧请求）；窗格里那份卸载也不会把数字清成 0。会话头「+N −M」→ 审阅的本次对话改动，分支 → 未提交的改动，右侧面板按钮 → Ctrl+J。
- **视图去哪**：`panel-entries.ts` 的 `viewTarget(view, {mobile, remote})`——桌面上 改动 → 审阅（本次对话）、Git → 审阅的 Git 视图、文件 / 搜索 / 生成的文件 → 文件、Issue 与 PR → 临时标签（隐藏时不跟着切对话重挂，免得每换一个仓库就发一次 `vcs.repo`）、定时任务 → 自动化页（阶段 7，不需要打开的对话）；手机和桌面一样（右侧面板是底部抽屉），远端会话一律原地（`ReviewView inPlace` 等）。会话头 ··· 和命令面板都走 `openSessionView`。`panel-entries.test.ts` 按 `ENTRY_CLICKS` 断言每个面板和原 8 个工作台视图 ≤ 2 次点击可达（spec §4.2 硬约束），`viewEntries()` 从 ··· 和命令面板自己用的 `viewsFor()` / `viewCommands()` 推出来；点击数是声明的表，DOM 上由 ui-smoke 逐个走一遍（见下）。命令面板的面板文案走 `panelCommandLabel()`（只有终端写「继续在后台运行」）；输入命中某个分组名（「面板」「主题」…）时整组列出，不截成 8 条，排在对话搜索结果**后面**（`palette/filter.ts` 的 `commandHits` → `{named, grouped}`）；分组名要打够 2 个字或者打全（中文输入打第一个字「对」时不能把「对话」「当前对话」两组十几条都列出来压住对话结果）。**被命中的分组整组连续**：它里面名字也命中的命令不再先占 8 个名字名额里的几个、排在对话前面（复审 M-c：输入「面板」时是 工作台 → 面板 5 条 → 会话 → 面板 8 条，同一个分组标题出现两次）；两部分都按分组聚拢（`clusterByGroup`，按第一次出现的顺序），所以每个分组标题只出现一次（`filter.test.ts` 按面板的画法数标题，ui-smoke 查 `.cmdk .grp` 不重复）。
- **窄窗口**：`.app:not(.mobile)` 的第三列是 `min(--rp, max(300px, 100vw − 侧栏 − 360px))`：**右侧面板保底 300px，其次尽量给对话 360px**（窗口 < 侧栏 + 660 时对话会不到 360，比如 900 宽侧栏展开时是 336）；隐藏（0）和 36px 图标栏不受影响。
- **标签行**（审查 I2）：四个固定标签在 `.dock-fixed` 里**不滚动**，只有临时标签在 `.dock-temps > .dock-tablist` 里横向滚动（滚轮也能横滚），哪边还有内容哪边就渐隐并出一个小箭头；前面的临时标签自动滚进视野。「更多」菜单和审阅的范围 / ··· 菜单都用阶段 3 的 `features/composer/Popover.tsx`（portal 到 body、`placeMenu` + 左右不出窗口、↑↓ Home End、`useMenuClaim`：同一时间只开一个锚定菜单，设置页盖上来时也关掉；锚点不见了——Ctrl+J 隐藏面板、切标签——也关掉，不再飘到窗口左上角），行是 `[data-mi]`——挂在面板里会被 `.rpanel{overflow:hidden}` 裁掉（1024 宽时「更多」菜单左边少 20px）。**桌面版 Windows / Linux 的系统按钮**占标签行右上 150px。两个判断都在纯函数 `workbench/tab-row.ts`（`tab-row.test.ts` 用 1440 / 1024 的实际数字）：
  - **`rowStacked`：只有四个固定标签 + 行尾按钮本身放不下时**才给行加 `.stacked`、整行挪到系统按钮下面（`padding-top` 现在是 `--h-head`，见「界面换新」；面板 < ~430px，比如 1024 宽带侧栏时的 400px 列）。**临时标签不参与**（第二轮复审 N1：以前「有临时标签至少留 72px」+ 16px 余量，默认 1440 × 440 下 280 > 277，一有改动 / 一开临时标签就整行下移 19px，切对话时数字 0 ↔ N 还上下跳）。行宽用**列的最终宽度**（`panelColumnWidth`，和 grid 的 `min(--rp, max(300px, 100vw − 侧栏 − 360px))` 同一个式子，不是 240ms 打开动画中间量到的宽度）；挪下去之后要空出 `STACK_HYSTERESIS`（8px）才挪回来。
