- **mac 包只能在 mac 上打**：`.github/workflows/release.yml` 用 `macos-latest`（arm64）+ `macos-15-intel`（x64）分别构建。不能在 arm 机器上交叉打 x64：npm 只装本机 CPU 的 SDK 二进制，ccb 的 ripgrep 也是 postinstall 按 `process.arch` 下载的。推 `v*` tag 才发布到 Releases，`workflow_dispatch` 只产出 artifact。仓库 2026-09-30 起公开（MIT），electron-updater 直接读公开的 Releases；安装包里带着 Agent SDK 的官方 Claude Code（Anthropic 条款）和 ccb（没有声明许可证），发布安装包前先想清楚这两样能不能再分发（README「许可证与致谢」，v0.1.0 起用户决定照发）。
  - **发版要手工收尾**（v0.1.0 踩过）：electron-builder `--publish always` 建的是**草稿**，三个 job 同时跑会各建一个同 tag 的草稿（v0.1.0 是 Windows 一个、mac 一个，arm64 的 zip.blockmap 还落进了 Windows 那个）；两个 mac job 都传 `latest-mac.yml`，后完成的覆盖先完成的（只剩一个架构）。收尾：`gh api repos/<o>/<r>/releases` 找出所有草稿 → 把多出来的草稿里的文件（`releases/assets/<id>` + `Accept: application/octet-stream` 下载，核对大小 / `latest.yml` 的 sha512）传进保留的那个再删掉多余草稿（删草稿不动 tag；只剩一个草稿时 `gh release upload <tag>` 才找得准）→ `latest-mac.yml` 合成一份（`files` 列四项 x64 / arm64 的 zip + dmg，arm64 那份在 artifact `claude-web-macos-latest-1` 里）→ `gh release edit <tag> --notes-file … --draft=false --latest`。v0.1.2 同样是两个草稿；`gh run download -n <名字> -p '*'` 的 `-p` 匹配的是 artifact 名，会把全部 artifact（每个几百 MB）一起下，网络一抖就失败——arm64 那两项更省事的做法是把草稿里的 zip / dmg 流过 sha512（`gh api -H "Accept: application/octet-stream" …/releases/assets/<id> | node <sha512 脚本>`），大小对上草稿即可；传文件进指定草稿用 `gh api --method POST -H "Content-Type: application/octet-stream" "https://uploads.github.com/repos/<o>/<r>/releases/<id>/assets?name=<文件名>" --input <文件>`。mac 没签名，Squirrel.Mac 不接受未签名应用的更新，所以 mac 版自己换 `.app`（「桌面版」一节的「Mac 自己更新」），它下的是 `latest-mac.yml` 里**这台机器架构的 zip**：**合并后的 `latest-mac.yml` 一定要有两个 zip（带 sha512 和 size）**，少了哪个架构，那个架构的 Mac 就退回手动下载。**已装的应用只看已发布的版本**（草稿不在 releases.atom 里），所以收尾完成、`--draft=false` 之前不会有人收到半成品；Windows 版下载的是 `latest.yml` 里的安装包，发布前确认合并后的草稿里有它。发布说明写上 `【必须更新】` 就是强制更新。发版时顺手把 `CHANGELOG.md` 的「未发布」改成这个版本号。
