# 图标栏 / 分区 / 联网（2026-10-10，界面第二轮）

spec 和实施记录：`docs/superpowers/specs/2026-10-10-ui-structure/design.md`（§7 记了做了什么、和设计不一样的地方、没验的）。起因：用户对着 Codex 桌面版的截图说按钮的位置不对、不好看、不顺手，并要内置的网络搜索 / 浏览器 / computer use。**下面和前面各节冲突的地方，以这一节为准**（末尾有清单）。

- **图标栏**（`features/rail/`：`Rail.tsx` + 纯逻辑 `rail-model.ts`，样式 `styles/rail.css`，`main.tsx` 里排在 `corners.css` 前面）：桌面上窗口最左边 52px（`RAIL_WIDTH`）：收起侧栏 · 对话 · 自动化 · 扩展 · ···，底下是设置和账户头像（头像外面一圈是额度）。手机没有图标栏，侧栏抽屉里多一行「扩展」。`RAIL_SECTIONS` 是分区表；`RAIL_MORE`（`mission, usage, memory, board, android, config`）是 ··· 菜单里的面板，每行名字 + 一句话（`railPanel()`），可以钉到图标栏上（最多 `MAX_PINS` 4 个，meta.json `ui.railPins`，`readPins` / `togglePin`）。「显示工作台工具」下那排没有文字的面板图标 **`DockRail` 删了**。
- **分区 = 盖在主区域上的页**（`features/sections/`）：`pages.ts` 是登记表（`registerPage` / `closeOtherPages` / `closePages` / `openPage` / `useSection` / `usePageOpen`）——同一时间只开一页，「对话」= 一页都没开。以前问「自动化页开着吗」的地方（输入框的 `composerCovered()`、`cover-commands.ts` 的 `underCovers()`、窗格层的 `inert`、手机抽屉的收起）现在问的是「有没有页开着」。`OverPage` 是页面外壳（标题用标题字、tab、关闭；窄页的内容列在卡片里居中，标题行和它同宽，Windows 上给系统按钮让位），`SectionSide` 是分区自己的侧栏。侧栏那一列跟着分区换内容（`App` 的 `SidebarColumn`：每个分区一个 `.sb-sect`，第一次看到才挂载，之后只 `hidden`）。**加一个分区**：`Section` 加一个 id + 自己的小 store 里 `registerPage` + `RAIL_SECTIONS` 一行 + `SidebarColumn` / `Workbench` 各一个分支。
- **自动化页**：没有任务时是「图标 + 标题 + 一句话 + 新建」，下面是带图标和颜色的模板卡（`automation/templates.ts`，卡片 `.tpl-card`）；「运行记录」（`data-id="sched-runs"`）有任务时在列表上面那一行，没有任务时在「从模板开始」标题旁边。分区侧栏 `automation/AutomationSide.tsx`。
- **扩展页**（`features/extensions/`，`Workbench` 里 `lazy()` 加载——不然首屏入口文件超过 1 900 000 字节的转发上限）：连接器（MCP 目录：`settings/mcp-catalog.ts` 是从 `McpCatalog.tsx` 拆出来的数据，`connectors-model.ts` 是筛选 / 分组，品牌标志 `ui/brand-icons.generated.ts` 由 `node scripts/gen-brand-icons.mjs` 按 `ui/brand-map.json` 从 simple-icons 生成，没有运行时依赖；没有标志的画首字母）、Skills、插件——和设置里那几页发同样的请求，画法是「标志 + 名字 + 一句话 + 一个动作」。导航表 `EXTENSION_NAV` 在 `ExtensionsSide.tsx`（侧栏不跟着页面一起懒加载）。设置里原来的页面都还在。
- **「想多深」单独一个按钮**（`models/EffortChip.tsx`，类名 `depth-chip` / `depth-menu`，图标 `gauge`）：模型菜单只选模型；强度按钮一行一个档位、各带一句说明，「深度编排」是最后一行的开关，开着时按钮是强调色。id 表 `composer/ids.ts` 的 `EFFORT_MENU_ID`，可达性表的 place 是 `depth`。类名和 id 里不能出现 effort（`wording.test.ts` 把代码值里的实现词也当文字查）。
- **右侧面板第五个固定标签「浏览器」**：`CORE_PANELS = files, explorer, terminal, browser, tasks`，`browser` 和终端一样 `keepAlive`。五个名字在默认 440px 的面板里、Windows 系统按钮旁边放不下，所以固定标签有**短形式**（`tab-row.ts` 的 `fixedShort` / `shortFixedWidth`，`.dock-fixed.short`）：只有前面那个带名字，其它是 30px 的图标（名字在 tooltip，审阅有改动时图标上一个点 `.has-n`）；按最宽的名字算宽度，切标签整行不动；连短形式都放不下才 `stacked`。量宽度时 `Dock` 先摘掉 `short` 类量完再放回（`fixedWidths()`）。**临时标签要么整个显示、要么收进「更多」**：`tempsFolded(…, {need})` 的 `need` 是最宽那个临时标签的宽度（`tempTabWidth(名字, 字号)`：全角字一个 em、其它 0.6 em，加 38px——按名字估，因为收起时它们不在 DOM 里，量得到才判断会来回跳）；以前只要剩 56px 就画标签条，「配置中心」在 72px 里被左边的渐隐切成半个字。ui-smoke 判断「哪个面板在前面」因此是「标签条里的 `.tab.active`，没有就看面板顶上的 `.dock-foldhead`」。
- **联网（服务端 `server/src/web/`）**：
  - 一个叫 `web` 的 MCP 服务器（`mcp.ts`，stdio），工具 `web_search` 和 `browser_open / read / find / click / type / press_key / scroll / back / screenshot`。交给对话的方式和共享记忆一样（`launcher.ts`，不改用户自己的配置）：走 SDK 的 `mcpServers`（以前 ACP / Codex 各有一条路，已删）。总开关 `web.mcp`（设置 → 联网），下次开对话生效。
  - MCP 进程回连本服务 `POST /api/web/tool`（`http.ts`，只认回环）：env 里是 `CW_WEB_URL` + `CW_WEB_TOKEN_FILE` + `CW_SESSION_ID`。密钥是每次启动随机的，**以文件交给它**（`<dataDir>/runtime/web-mcp/<server pid>.token`，0600；SDK 把 `mcpServers` 放在命令行上，别的用户 `ps` 看得到），写不了文件才内联。
  - **搜索**（`search.ts` + `engines/`）：设置 `web.search.engine`，默认 `auto` = Bing 的结果页 → 不行换 DuckDuckGo 的 HTML 页（都不用密钥，走本进程的网络代理）；Tavily / Brave 要密钥（`web.search.tavilyKey` / `braveKey`，`enc:` 存、wire 上打码、回传打码值不覆盖）。`relevance.ts`：结果里一个查询词都对不上就当这家没答上（Bing 对程序的请求有时给一页不相干的东西）；被拒冷却 60 s、连不上冷却 5 分钟（只在 auto 下跳过冷却中的）。**不用密钥的搜索在真实网络上靠不住**（2026-10-10 在一台挂着代理的机器上实测，脚本在 scratchpad 的 `real-search.mjs` / `real-bing.mjs` / `real-ddg.mjs`）：Bing 的结果页 16 次里只有 2–4 次对题，一半是「只认第一个词」的首页（`rust tokio select macro` → Rust 游戏官网，相关性检查标成 `weak`），其余是不相干的页或验证页——换请求头、换市场、甚至用真的浏览器页面去开都一样，是出口 IP 的问题不是请求形状的问题；DuckDuckGo 的 HTML 页答对了头两次，之后这个 IP 连续几分钟都是 202。所以它只是个兜底：工具描述、`weak` 的提示（`SEARCH_WEAK_NOTE`）和失败时附的一句（`SEARCH_FAILED_HINT`，只加在给模型的结果里，设置页「试一下」不带）都叫模型优先用自己的搜索工具；要稳就填 Tavily / Brave 的密钥。`web_search` 是唯一不问权限的工具（`WEB_SEARCH_TOOL` 进 Claude 的 `allowedTools`）；其它和运行命令一样走审批。
  - **浏览器操作**交给一个桌面窗口：窗口用 `browser.host {on}` 登记（只收本机窗口：`hub.ts` 的 `localWindowOnly()`，远程 / 设备 / peer 连接一律拒绝），服务端发 `browser.command {id, sessionId, op, args}`，窗口回 `browser.result`，30 s 超时（`COMMAND_TIMEOUT_MS`）。没有窗口连着时 `open` / `read` 退回服务端自己抓网页转文字（`html-text.ts`），其它操作回 `NEEDS_DESKTOP`。`url-guard.ts` 按谁去取分两种：桌面窗口里的浏览器（`reach: 'browser'`）是用户自己的浏览器，除了 link-local 和云平台的 metadata 地址都能去；服务端自己抓（`reach: 'server'`）另外拒绝局域网（模型不能借我们读内网，重定向进内网也拒），回环放行（Agent 要看它刚起的 dev server）但本服务自己的端口除外；两种都只收 http(s)。
  - **网页内容是不可信的**：`format.ts` 把它包在 `<<<WEB_CONTENT … ` 标记里并写明「是资料不是指令」；**`note` 字段显示在标记外面**，所以窗口回的 note 只能是我们自己的话（「已点击 [kqz3]」），不带元素名字、地址、选项列表。正文默认 12 000 字、操作后的回读 6 000 字。
  - （历史：当时的默认引擎 ccb 自带的 WebSearch 默认经上游项目托管的 Tavily 代理，我们没改它；ccb 已删，官方 Claude Code 的 WebSearch 不涉及这个。）
  - 联邦：`browser.*` / `web.*` 都是 LOCAL（`federation/rewrite.ts`），远端对话的 Agent 用的是它那台机器的浏览器。
- **内置浏览器（客户端 `web/src/features/browser/`）**：
  - `BrowserPanel.tsx`：地址栏（`url.ts` 的 `addressToUrl`：网址 / `localhost:3000` / 否则当搜索词给 Bing）、后退 / 前进 / 刷新、「发给对话」（把地址和选中的文字放进输入框）、两个以上才出现的标签条、新标签页（搜索框 + 最近打开，meta.json `ui.browser.recent`）。桌面版是 `<webview>`，网页版是受限 iframe + 一句提示（被 `X-Frame-Options` 拒绝的站点是空白）。iframe 的 sandbox 由 `url.ts` 的 `frameSandbox(url, 自己的 origin)` 定：别的站点带 `allow-same-origin`（它自己的 cookie / 存储才能用），**会和应用同源的文档不带**（应用自己的地址、继承我们 origin 的 `about:blank`）——脚本 + 我们的 origin 一起就能伸手进外面的应用，Chromium 对这一对也会报 console 警告（ui-smoke 抓到的）；窗格里的老 `BrowserTile` 用同一个函数。网页里要开新窗口的链接变成一个新标签（`desktop/src/main.ts` 的 `desktop:browserPopup`）。**`<webview>` 默认连 `window.open` 都不让页面调**（弹窗被禁时 `setWindowOpenHandler` 根本不会被叫到，链接点了没反应——发版前在打包后的应用里抓到的）：要两处一起放开，`<webview allowpopups>`（`BrowserPanel.tsx` 的 `ALLOW_POPUPS`）和 `will-attach-webview` 里的 `disablePopups = false`；放开之后每个弹窗仍由 `did-attach-webview` 的处理器 `deny` 掉、改发 `desktop:browserPopup`，不会真的建窗口。
  - `state.ts`（小 zustand `useBrowser`）：每个对话的 Agent 一个自己的标签（`agentTab(sessionId)`，带标记条 `AgentStrip`）。**`src` 只设一次**——`<webview>` 的 `src` 再设一遍就重新加载；之后的地址在 `url` 里，导航走 `loadURL`。分区（partition）：默认和用户自己的标签共用 `persist:cw-browser`（登录过的站点 Agent 也能用），设置「Agent 用单独的浏览器身份」（`web.browser.isolated`）打开后是 `persist:cw-agent`。
  - `host.ts`：把这个窗口登记成 Agent 的浏览器（只在 `hasWebview()` 时；连上、重连、窗口获得焦点时各报一次），每个对话一条队列逐条执行。`ops.ts` 是一次操作的顺序（做 → 等页面停下 → 读回来），对着 `PageHandle` 接口写，`ops.test.ts` 用假页面；`guest.ts` 用 `<webview>` 实现它（`executeJavaScript`、`sendInputEvent`、截图走桌面壳 `desktop/src/browser-capture.ts`：只截属于提问窗口的 guest、缩到 ≤ 1280 宽、JPEG）。
  - `page-agent.js`：注入网页里的普通脚本（`?raw` 导入，每次调用前都注入，幂等）：正文、可操作的元素、点击、输入、滚动、选中的文字。**元素编号是每个文档三个随机字母加序号**（`kqz12`）：第一次真跑时 Agent 拿上一页的 `e1` 点到了下一页的另一个元素。写这个文件别打字面量的不间断空格，用 `\u00a0`。
  - **Agent 的操作不抢用户的标签**：浏览器在别的标签后面时仍按原尺寸排版、只是不显示（`.dock-panel[data-panel='browser'][hidden]` 是 `visibility:hidden` 而不是 `display:none`，后面的网页标签 `.bw-view.back` 同理），读 / 点 / 输入照常。只有三种情况把浏览器带到前面：这个对话第一次打开网页、右侧面板整个收起了（网页是 0×0）、要截图——**没画出来的 guest `capturePage` 会一直挂着**（`UnknownVizError`），所以截图前 `inFront()`，桌面壳和 `guest.ts` 各自 5 s 就放弃。
  - 对话里 `mcp__web__*` 的步骤行和审批卡有自己的文字（`web-tools.ts`：「搜索 xxx」「打开 example.com」「想在网页上点击」）；`registry.tsx` 的 `splitMcp` 对它们返回 null（不走通用 MCP 卡片）。
  - 设置 → 连接 → **联网**（`WebSettings.tsx`，catalog 的第 15 个可见分区——上限就是 15）：总开关、搜索引擎和密钥、「试一下」（`web.search` 请求）、Agent 用单独的浏览器身份。「联网」是页标题，所以进了标题字的字符表（改标题要重新裁，见「界面换新」）。
- `+` 里的「控制浏览器」改叫**「控制 Chrome」**（`--chrome`，用户自己的 Chrome + Claude 扩展）：内置浏览器每个对话都有、不用开关，两个都叫浏览器会分不清。
- **操控电脑现在用不了**（2026-10-10 不花 token 实测）：引擎的 `--computer-use-mcp` 只是它「自己作为 MCP 服务器运行」的入口（argv[2]），会话里的 computer use 只在它自己的终端界面里装配（`!getIsNonInteractiveSession()`）；从这里开的对话带上这个参数，**进程在第一条消息之前 exit 1**。所以 `+` 里的「操控电脑」以前不是没效果，是一开对话就起不来。现在 `featureArgs()` 不再传它（`SessionFeatures.computerUse` 留着只为读旧的默认值），`capabilities.ts` 的那一行带 `unavailable`（`+` 里显示「暂不可用」和原因，`usable()` 把存下的默认值里的它去掉）。后来改成我们自己的 `computer` MCP（见「搜索在内置浏览器里 / 网页上的鼠标键盘 / 操控电脑」），这一段只是历史。
- **调试 / 验证**：
  - `node server/ws-phase23.mjs`（e2e 默认列表里，自己起 server）：真 MCP 进程 + 假搜索引擎（本地 HTTP）+ 假窗口（一条 ws 连接答 `browser.command`）：搜索、换引擎、冷却、密钥打码、没有窗口时的退回、远程连接不能当浏览器、开关关掉后新对话没有这个服务器。
  - `node scripts/browser-smoke.cjs`（先 `npm run build:all`，约 1 分钟，只在本地跑）：真 Electron 窗口（`webviewTag`）+ 临时 HOME 的 server + 本机一个小网站：用户自己浏览；`window.__cwBrowser.carryOut` 驱动 Agent 的每种操作（打开 / 读 / 找 / 输入 / 选下拉 / 点击 / 按键 / 提交表单 / 返回 / 滚动加载 / 截图）；标签在后面和面板收起时；再从 MCP 进程 → server → 窗口 → 网页 → 结果 走整条链路。
  - `window.__cwBrowser`（`{ carryOut, state, canHost }`）是调试入口，和 `__store` 一样挂在 window 上。
  - ui-smoke 新加的「structure」一段：图标栏 ··· 的每一行、钉住 / 取消、扩展页（目录 ≥ 20 行、侧栏三项、内容列居中、搜索、Skills、插件、Esc）、浏览器标签在网页版（新标签页、iframe + 提示、第二个标签出现标签条、在审阅后面仍然排版）、`+` 里操控电脑那一行。
  - **打包后的应用**（发版前，Windows，`electron-builder --dir` 的产物 + 临时家目录 / 数据目录 / `--user-data-dir`，脚本在 scratchpad 的 `real-packaged.cjs`，经 `--remote-debugging-port` 驱动）：`<webview>` 里开网页、Agent 打开 / 点击 / 填字 / 提交、截图走 `desktop:captureBrowser`、页面的新窗口变成标签、`app.asar` 里的 `server/dist/web/mcp.js` 用应用自己的二进制当 node 起得来、MCP → 本机 server → 窗口 → 页面 → 结果整条链路，14 项都过。`scripts/smoke-packaged.mjs`（发版的 Release workflow 在 Windows 和两种 Mac 上都跑）加了两条：`web.status` 是开着的；从 `app.asar` 起 `web` MCP 服务器、`initialize` + `tools/list` 能握手并列出 `web_search` / `browser_open` / `browser_screenshot`。

- **踩过的坑**：
  - vitest 里 import `features/chat/tools/registry.tsx` 会把 store 拉进来（`location is not defined`）；纯逻辑放在不 import store 的文件里（`web-tools.ts`）再测。

- **前面各节里不再成立的说法**：
  - 「右侧面板四个固定标签 审阅 · 文件 · 终端 · 任务」→ 五个，多了浏览器；「1440 × 440 的桌面版 固定标签 194 + 按钮 58…」那组数字 → 默认面板里是短形式。
  - 「面板图标栏（`DockRail`，挂在分组栏右端）只在 `ui.workbench`」→ 没有了；`chromeVisibility` 只剩分组栏和标签条两项，那些面板在图标栏的 ··· 里。「`workbench` tier 的面板只从命令面板 / 快捷键打开」→ 还可以从图标栏 ··· 打开、钉住。
  - 「模型菜单顶部『智能程度』分段控件 +『深度编排』开关」「芯片文案 `Sonnet 5 · 深入`」→ 模型芯片只写模型；档位和深度编排在旁边的强度按钮里。
  - 「侧栏三个导航：新对话 · 搜索 · 自动化」→ 桌面上侧栏只剩「新对话」一行（搜索是顶行的一个图标），自动化、扩展、收起侧栏、设置、账户都在图标栏上；手机没有图标栏，抽屉里是 新对话 · 搜索 · 自动化 · 扩展，底下仍是账户行。
