# 首次使用：接一个模型（2026-09-30）

- **没有 Claude 订阅的人是默认用户**：首次引导第一步是「接一个模型」（`features/providers/QuickConnect.tsx`，纯逻辑 `quick.ts` + 测试）：选来源（中转站 / Anthropic API，`PRESETS`）→ 中转站填地址（`cleanBase()`：补 https（本机 / 局域网补 http）、去掉粘进来的 `/chat/completions` `/messages`）→ 粘 Key → 连接。先 `providers.probe {listOnly:true}` 只读模型列表（不花 token，两种鉴权头都带），`quickPlan()` 按列表定模型：都是 Claude 格式（`anthropicBase()` 去掉 `/v1`），`modelMap` 三个家族都填上最新的那个——CLI 后台的 haiku 调用在没有那个确切 id 的中转上会失败——默认 sonnet；列表里没有 Claude 模型（new-api 之类在转换）就三个家族都映射到挑出来的那个模型；然后带着这个 plan 真跑一次 `providers.probe`（一次 CLI 回合，`chatProbe`）；通过就 `providers.upsert`（`uniqueName`，中转站用主机名命名）并在需要时设成 `defaultProviderId`。失败的话 `explainProbe()` 说人话（Key 不对 / 余额 / 地址不对 / 连不上 / 不是 https / 模型用不了 / 地区），原文在 tooltip；模型列表通了但测试没过可以「仍然保存」。「用 Claude 账号登录」（`claude auth login` 进终端）是次要链接。（历史：2026-11-01 前还有 DeepSeek / Kimi / 智谱 / 通义 / 硅基 / OpenRouter / Gemini 预设和 OpenAI 格式，见「只留 Claude」。）
- **模型挑选是共享纯函数**（`server/src/models/catalog.ts`，web 经 `@catalog`）：`pickChatModel()` 按 `CHAT_MODEL_PREFERENCE`（Claude sonnet → opus → 其它 Claude）取每组里最新的（`modelVersion()`：1–2 位数字，日期 / 尺寸不算），排除 embedding / 图像 / 语音等（`isChatModel`）；`claudeFamilyMap()`。服务端的 `providers.probe` 也用 `isChatModel` / `claudeFamilyMap` 挑测试模型（列表按字母排序，第一个常是 `dall-e-3` / embedding；只有图像模型的 Key 直接报「不能用来对话」）。
- **「接一个模型」对话框**（`features/providers/ConnectModel.tsx`：`connectModel({reason})` 返回 Promise<Provider|null>，`ConnectModelHost` 挂在 App，`.dialog-bg` 所以在设置页之上、不被 inert）：`start`（首页提示）/ `send`（欢迎页发送时 Claude 账号确定未登录——`welcome-provider.ts` 的 `needsModel()`——接好后这条消息直接发出去，关掉对话框字留着）/ `session`（已有对话报「Not logged in · Please run /login」：StatusStrip 的 `data-err="no-login"` 给「接一个模型」= `session.setProvider` + `retryLast`，和「用 Claude 账号登录」；重试按钮不给，重试只会同样失败）/ `settings`（设置 → 供应商「快速添加」、账号与登录的「接一个模型」）。有已添加的供应商时顶上一排「用已添加的」一键选。新接的供应商在 Claude 账号没登录、也没有可用的默认供应商时自动设为默认（完整表单的保存同一规则）。
- **欢迎页的供应商跟着走**（`welcome-provider.ts` 的 `welcomeProvider()`）：用户没在模型菜单里选过时，上次用的（还可用）→ 默认供应商 → Claude 账号；**账号确定未登录且有可用供应商时永远不选账号**。设置、登录检查、供应商列表都在首次渲染之后才到，所以是 effect 里一直重算（`providerPicked` 之后才停），首次引导里接好的供应商立刻出现在芯片上。
- `claude auth status` 在 `~/.claude/settings.json` 的 `env` 里有 `ANTHROPIC_AUTH_TOKEN`（或进程 env 有 `ANTHROPIC_API_KEY`）时报 `loggedIn: true`（2026-09-30 实测），所以用 settings.json 配中转的老用户不会被拦。
- **进程 PATH 补全**（`server/src/proc/locate.ts`，原来在 `agents/`）：从开始菜单 / Finder 启动的应用只有登录那一刻的 PATH，fnm 的 PATH 只在 shell 配置里、`uv tool` 的 bin 常不在 PATH。`refreshProcessPath()`：把 Windows 注册表里**现在的** PATH（HKLM + HKCU，展开 `%VAR%`）和常见安装目录（`%APPDATA%\npm`、nvm4w / Program Files\nodejs、fnm 默认别名、pnpm、Volta、bun、WinGet Links、scoop、`~/.local/bin`、cargo；mac/Linux 的 Homebrew、nvm 最新版、fnm、mise/asdf…）里**存在的**追加到本进程 `PATH` 末尾（用户自己的顺序优先）；启动时一次、30 s 内复用，ego-browser 检测时强制。之后所有 spawn、终端面板、`npm i -g` 都看得到。（历史：以前还给其它 agent 做检测——`findBundled` 找 Codex 桌面版 / IDE 扩展自带的 codex、`AgentInfo.probeError / installNeeds`——2026-11-01 随其它 agent 删了；`findBundled` 还在文件里。）
- 本机验证：假的 Anthropic 兼容中转 + 临时 HOME 起 server：首次引导填错 Key 是「API Key 不对…」、填对后芯片立刻变成这个供应商、发消息拿到回复；删掉供应商后在欢迎页发送 → 「先接一个模型」→ 接好后消息自动发出；账号未登录的对话 → 「接一个模型」→ 换供应商并重试成功。
- ui-smoke：引导第一步断言快速连接在位（预设、Key、连接）且没有「添加供应商 / 在终端登录」；冷启动发送在没登录也没供应商时断言弹「先接一个模型」、字还在、没开对话，然后用 `srvReq` 加一个指向 `127.0.0.1:9` 的供应商、点「用已添加的」让消息发出，结束后删掉它（后面的检查默认芯片是账号）。
