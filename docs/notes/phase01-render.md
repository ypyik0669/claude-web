# 渲染与对话交互（阶段 1，2026-09-03）

- **reducer 是唯一真源**：`web/src/model/conversation.ts` 纯函数，`web/src/model/__fixtures__/tools.jsonl` 是用 `server/ws-capture.mjs` 录的真实流（Read 文本+图片 / Glob / Grep / Bash / WebFetch / TodoWrite），`conversation.test.ts` 回放它。改 reducer 先跑 `npm test -w web`。
- **发送时客户端铸 uuid**（`SendParams.uuid` → `SDKUserMessage.uuid`），本地回显 id 就是 transcript uuid，编辑重发 / 重跑 = `openSession({sessionId, resumeAt: findChainUuidBefore()})` 再发。ccb 不回显 `user_message_uuid`，但 uuid 会落到 jsonl，够用。
- **工具输出优先用 `tool_use_result`（`result.structured`）**：SDK 的 `sdk-tools.d.ts` 有每个工具的 Output 形状（`structuredPatch` 带行号、`FileReadOutput` 的图片 base64、`GrepOutput.mode`…）。ccb 的 GrepOutput 用 `numLines` 而不是 `numMatches`，卡片两个都认。
- 工具卡片在 `web/src/features/chat/tools/registry.tsx` 注册（图标 / 分类 / 头部文案 / Body）；`mcp__*` 和未知工具走 `GenericBody`（键值网格 + JsonTree + 图片）。Steps 折叠的分类计数也从注册表取。
- 健康信号（`model/health.ts`）：卡死判定是客户端计时（15s 无事件、3 分钟无模型调用）。`conv.lastModelCallAt` 是整个对话的，不按轮清零：早于 `turnStartedAt` 的不算这一轮的；这一轮一次模型回复都没有时从 `turnStartedAt` 算 3 分钟，报 `no_reply`（「N 分钟还没收到模型的任何回复，供应商「X」可能没有响应」）——以前上游从头到尾不回时界面只有一个一直走的计时器（2026-09-30 用户报告）。错误分类 `classifyError()` 输入 `api_retry.error` / `result.terminal_reason` / HTTP 状态 / 文本；限流 `rate_limit_event` → `conv.rateLimit`，`settings.autoContinueOnReset` 打开时到 `resetsAt+5s` 自动重发上一条（store 里的 `armAutoContinue`）。
- **Agent SDK 默认空系统提示**，runner 传 `systemPrompt: {type:'preset', preset:'claude_code'}`（也是过中转指纹的必要条件）。
- 桌面模式 `PORT=0`，origin 每次变 → 草稿 / 评分 / 思考开关 / diff 模式都进 meta.json（`drafts.*`、`feedback.*`、`settings.set`），不要用 localStorage 存这些。
- 附件：`POST /api/attachments?sessionId=&rel=`（token 同 `/ws`）存到 `~/.claude-web/attachments/<sid>/`，消息文本后追加 `<attached kind name path size />` 标记，模型自己 Read；`decodeAttachments()` 在渲染时把标记解成芯片。超过 3000 字 / 60 行的粘贴自动变成 `kind="text"` 内联附件。
- **PDF 附件带上抽出来的文字**（2026-11-17，社区用户 StickerWu：Windows + ccb 2.8.4-cw.7 + OneAPI 中转，拖进来的中文简历 PDF「读取 失败」，模型最后说「中文字体抽不出文字」）。
  - **根因**：PDF 以前只以 `<attached kind="file" path>` 交出去，模型自己 Read。两个引擎读整份 PDF 都是交 base64 `document` 块（官方 2.1.322：tool_result 里一句 `PDF file read: <path> (62KB)` + document；ccb：tool_result 只有那一句，document 在同一条 user 消息里跟在后面），**只有收 document 的接口看得到**。ccb 的 OpenAI 格式适配器（`rcDebugLog-*.js` 里的 `ft`）把 user 消息里的 document 块整个丢掉，tool_result 里的图片也丢（读 PNG 交给模型的是空字符串）——模型只看到「PDF file read」，以为读到了；中转把 Anthropic 转成别的接口时也一样（我们自己网关转 OpenAI 时是 `[document]`）。`pages` 参数要 poppler 的 pdftoppm，Windows 上没有：官方报 `pdftoppm is not installed. Install poppler-utils …`；ccb 的探测（`pdftoppm -v` 退出码 0 **或 stderr 不空**就算装了）把 cmd 的「不是内部或外部命令」当成装了，报 `pdftoppm failed: 'pdftoppm' is not recognized as an internal or external command …`——中文 Windows 上这句是 GBK，按 UTF-8 解成乱码，模型的「中文字体抽不出」多半是看了它（没在中文 Windows 上验证）。整份读的路上大小（ccb ≤ 20 MB / 3 MB 以上先渲染一遍只为打点）、页数（pdfinfo 没有就不查）、模型（只排除 claude-3 系列）都不拦 190 KB 的简历。
  - **修法**：上传接口（`index.ts` 的 `/api/attachments`）收到 `.pdf` 先抽文字写到旁边的 `<文件>.pdf.txt` 再回包（`files/pdf-text.ts` 的 `writePdfText`，回包多一个 `textPath`；抽不出时删掉同名旧 txt）；`SessionRunner.send` 的 `withPdfText()` 把它作为一个带 path 的 `kind="text"` 内联附件放进消息：开头一句英文说明（给模型看的，界面只显示芯片：排版 / 图片 / 扫描页不在里面，需要时整份 Read PDF、别用 pages），超过 2 万字只放前面、说从 txt 第几行接着 Read。界面上多一个「xxx.pdf.txt」芯片，点开就是那份文字。不管哪个引擎、哪种供应商，文字都在第一个请求里（假上游实测：ccb + Anthropic、ccb + OpenAI、官方二进制三条路都有）。
  - **抽文字用 `pdftotext`**：Windows 用 Git for Windows 自带的 xpdf 4.00（`<Git>\mingw64\bin`，默认不在 PATH 上；Claude Code 在 Windows 上本来就要 Git for Windows），按 PATH → PATH 里 git 的目录 / `CLAUDE_CODE_GIT_BASH_PATH` → 常见安装位置找（`pdftotextCandidates`）；别的系统用 PATH / Homebrew 的 poppler，macOS 都没有就用 JXA 调 PDFKit（**不灵**：11-17 CI 的 macos-latest 上没有 poppler，这一支对测试用的中文 CID PDF 返回 null，原因没查——`ObjC.import('Quartz')` 拿不到 `PDFDocument`？手写的 PDF PDFKit 不认？那条测试改成只在有 pdftotext 时跑。所以 Mac 上要 `brew install poppler` 才有文字）。没加依赖（pdf.js 太大，还要 CJK 的 cmaps）。中文 CID 字体靠字体的 ToUnicode（Word / WPS / 浏览器导出的都有）；扫描件没有文字层 → 不写 txt，只剩 PDF（中转上照样看不到，要 OCR / 渲染成图才行，没做）。
  - **坑**：xpdf 4.00 在 Windows 上按 ANSI 代码页开文件，英文系统上中文文件名直接 `Couldn't open file '…\????-??.pdf'`。所以给它工作目录 + 相对文件名（目录名是中文也行），文件名本身不是 ASCII 时先复制成临时目录里的 `cw-pdf-<随机>.pdf`。
  - **坑**：web 的 `ATTACH_RE` 里，没 body 的 `<attached … />` 后面那个可选的 `[\s\S]*?</attached>` 会一直吃到**下一个** `</attached>`：文件附件后面跟着长粘贴（或这段 PDF 文字）时，中间的芯片全不见。`withPdfText` 把有 body 的附件排到前面躲开它；正则本身（reducer 里）没改。
  - **复现 / 测试**：假上游第一轮回一个 `tool_use` Read，把下一个请求里的 tool_result 记下来（stall 那套的写法，scratch 的 `pdf-upstream.cjs` + `pdf-run.sh <名> <ccb|claude> <anthropic|openai> '<Read 参数>'`），测试 PDF 用 Edge `--headless --print-to-pdf` 打一页中文 HTML。`pdf-text.test.ts`：`cjkPdf()` 手写一份 Type0 / Identity-H + ToUnicode 的两页 PDF，有 pdftotext（或在 Mac 上）时真抽一遍，含中文文件名。
  - **引擎（fork）里该改、还没改的**：OpenAI 适配器把 document 换成一句「这里有个 PDF，这个接口收不了，内容你看不到」、tool_result 里的图片挪到后面的 user 消息（网关 `openai-chat.ts` 的做法）；pdftoppm 探测看退出码 / 用 which；非 Anthropic 供应商上 Read PDF 不交 document 块。
  - **没覆盖**：文件树拖进来的 `@路径`（CLI 自己展开 PDF）；文件夹里的 PDF（txt 在它旁边，模型 Glob 能看到，但不进消息）；Codex / ACP 对话（它们的文字附件标记没有 `kind`，会整段显示在气泡里，所以没接）。
- **粘贴文件 / 文件夹**（2026-11-17 用户录屏：资源管理器里复制 .md，输入框 Ctrl+V 没反应——`onPaste` 以前只认图片和长文字）。逻辑在 `web/src/features/composer/paste-files.ts`（+ 测试），`Composer.tsx` 只调它：
  - 事件里先同步取走 File / `webkitGetAsEntry()` / 路径（`snapshotPaste`；handler 返回后 DataTransfer 就空了），`planPaste` 定怎么办：有**来自磁盘**的文件（桌面版 `desktop.pathForFile` = `webUtils.getPathForFile` 有路径；浏览器有 file system entry）就按文件，哪怕旁边有文字；没有就看文字——有字按文字（Office 复制单元格 / 段落会同时放文字和一张图，以前粘成图，现在按文字），长文字照旧转附件；只有图（截图）按文件；什么都没有时桌面版 `ask`（不拦事件，反正粘不出东西）。
  - 文件和拖进来**同一条路**：`resolvePaste` 产出和 `expandDataTransfer` 一样的 `ExpandedFiles`，`Composer` 的 `takeDropped`（onDrop 也用它）把单独的图片变图片附件、其余上传，对话在别的机器上 toast `REMOTE_ATTACH`（图片照发）。
  - **文件夹**：桌面版把页面拿到的路径交给主进程 `desktop.clipboardFiles(paths)`（`desktop/src/clipboard-files.ts`，只答本机绝对路径，网络路径不 stat）问清哪些是文件夹，文件夹**按路径引用、不上传**：作为 `{kind:'folder', name, path:<原路径>}` 进 `atts`，发送时就是 `<attached kind="folder" path="C:\…" />`，Claude 在原地读。选这个而不是展开上传：①服务端和桌面壳在同一台机器，原路径就读得到，内容是最新的，也没有 500 个文件 / 跳过 node_modules 的截断；②页面读不了粘贴进来的文件夹内容（Chromium 给的 File 是空的），展开上传得在主进程另写一套读目录再走 IPC 传字节；③和官方桌面版一样（卡片上是完整路径 + Folder 标签），也和文件树「添加到对话」的「引用不上传」一致。代价：同一个文件夹拖进来是上传副本，粘贴是引用原处。页面一个 File 都没拿到时（Chromium 没给），主进程自己读剪贴板的文件列表，全部按路径引用（没有内容可传）。
  - **普通浏览器**拿不到路径（也可能根本不在服务端那台机器上）：有 entry 的文件夹按拖进来的办法展开上传；File 读不出来（`readable()`：没大小没类型没扩展名、或读第一个字节失败）就 toast 让用户拖进来；Chromium 什么都没给就保持原样。
  - 路径引用在 `atts` 里，所以新对话选了别的机器 / WSL 时 `startOnPeer` / `startOnWsl` 现有的 `atts.length` 检查一样会拦；在跑的远端对话粘贴时就 toast。
