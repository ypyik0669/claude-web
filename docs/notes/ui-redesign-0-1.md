# 界面改版 阶段 0–1：令牌 / 文案 / 外框按需出现（2026-09-28）

spec：`docs/superpowers/specs/2026-09-28-ui-redesign/proposal.md`（§5.2、§5.10、§5.12、§6）。

- **令牌**：亮色 = 纯白主区 + 中性浅灰侧栏（`--bg #fff` / `--bg-1 #f8f8f7`），状态色为白底重调（绿 `#177540`、红 `#c23a30`、黄 `#8f5c0e`、蓝 `#2862d6`，在 `--bg-2` 上也 ≥ 4.5:1）；暗色侧栏比主区更深（`--bg-1 #151514` < `--bg #1a1a19`），`--fg-2 #8e8e88`、`--fg-3 #767671`（菜单 / 输入框的 `--bg-elev` 上也 ≥ 3:1）。其它 4 个主题也调过 `--fg-2/-3` 和红色（dracula / nord 的红在 `--bg-2` 上原来只有 2.5:1），**paper 以前没有自己的状态色**（继承暗色那套，米色底上看不清），现在有了。**`--primary` / `--primary-fg`**（亮 / 暗是墨色，其它 4 个主题回退到各自的 accent）给主按钮、发送、开关「开」（`--ctl-on`）；橙色 `--accent` 只留给品牌、焦点环、选中指示。`.icon-btn.active` 用中性的 `--layer-selected`。圆角 8/10/14/22（`--r-md..2xl`）、间距 `--sp-1..8`、行高 `--h-head 52px` / `--h-bar 40px`、`--fs-base 13.5` / `--fs-body 14.5` / `--lh-body 1.7`，字体栈加了 Segoe UI Variable Text / Microsoft YaHei UI。新样式用这些令牌，别写死 px / 颜色。
- **对比度单测** `web/src/ui/contrast.test.ts` 直接读 `styles.css` 的主题块（`ui/contrast.ts` 的 `themeBlock()` 先剥掉 `/* */` 注释——注释里的旧值或 `}` 不能算数——只取字面量颜色）。亮 / 暗两套在 `--bg`、`--bg-1`、`--bg-2`（会话头的 +N −M、chip）、`--bg-elev`（菜单、输入框）四种底上：正文 ≥ 7:1、`--fg-1/-2` 与四个状态色 ≥ 4.5:1、`--fg-3` ≥ 3:1、气泡正文 ≥ 7:1、`--primary-fg` on `--primary` ≥ 4.5:1；**6 个主题全部**：绿 / 红（diff 数字）在 `--bg/-1/-2` 上 ≥ 4.5:1、`--fg-3` 在四种底上 ≥ 3:1、`--fg-1 > --fg-2 > --fg-3` 的层级不倒挂。改主题原色先跑它（调色照着它算，别凭眼睛）。
- **默认主题 = 跟随系统**：`ui.theme` 没设置就是 `system`（`ui-settings.ts` 的 `DEFAULT_THEME`），系统切深浅色时 `setSystemThemeHandler` 回调 store 的 `setTheme(…, true)`（不写回 `ui.theme`）。桌面标题栏按钮颜色由 `App` 的 effect 统一设置：右上角是会话头 / 空白页 / 默认界面的右侧面板（白底，阶段 2）时用 `--bg`，是「显示工作台工具」下的停靠面板标签行 / 分组栏 / 标签条时用 `--bg-1`（store 的 `setTheme` 不再直接调 `setTitleBarColors`）。
- **术语只有一份**：`web/src/ui/terms.ts`（`TERMS`、`PERMISSION_MODES`（6 种权限模式：名字 + 一句后果 + recommended / danger）、`MODE_LABEL`、`EFFORT_LABEL`（low 快 · medium 均衡 · high 深入 · xhigh 更深 · max 极限 · ultra 超限）、`effortLabel()` / `effortTitle()`（tooltip 保留 `effort: high` 原值）、`ULTRACODE`（深度编排）、`WORKBENCH_VIEW_LABEL`）。`terms.test.ts` 锁住映射。协议值、meta.json 键、命令 id、快捷键 id 都没改名，只改显示文字；`SHORTCUTS` 的 group 从「窗格」改成「分屏」（命令面板按 group 选图标，跟着改了）。
- **外框按需出现**：`model/layout.ts` 的纯函数 `chromeVisibility(layout, {workbench})` 决定画不画外框——分组栏：>1 个分组或 `ui.workbench`；每个窗格的标签条：`ui.workbench`、组里 >1 个窗格、窗格里 >1 个标签、或唯一的标签不是对话（文档 / 终端没有会话头，标签条是它们的名字和关闭按钮）；面板图标栏（`DockRail`，挂在分组栏右端）：只在 `ui.workbench`。**手机（≤ 760px，`chromeVisibility(…, {mobile})`）三样都永远不出**（spec §5.11，不管设置和布局）；`store.mobile` 由 `App` 用 `ui/viewport.ts` 的 `MOBILE_QUERY` 同步，组件读 store 不读 media query。手机上每个会话头 / 欢迎页都有「展开侧栏」（抽屉没有别的把手）；前面是文档 / 终端 / 浏览器时 `Pane` 画一行 `MobileTileBar`（☰ · 名字 · 关闭），因为它们没有会话头。Ctrl+D 之后 `paneCount > 1` 标签条自动出现，关掉分屏又消失。**只决定外框，不决定内容挂载**（`Pane` 里 `{strip && <TabStrip/>}`，tile 照旧常驻）。全局 `TopBar` 删了：额度环去了侧栏底部的账户行（`sidebar/UsageRing.tsx` + `account.tsx`，明细在点账户行弹出的菜单里，见「界面改版 阶段 4」），图标栏进了 `DockRail`，侧栏开关变成左上角那一行里的「展开侧栏」（`SidebarReveal`，只在侧栏收起时出现）。
- **`ui.workbench` 取代 `ui.singleWindow`**：`migrateWorkbench(settings, savedLayout)` 在 `loadMeta` 里跑一次并写回 meta.json——已设置就不动；`ui.singleWindow: true` → 关；没有保存过布局（全新安装，**以及每次启动 origin 都变的桌面版**）→ 关；保存的布局里真的在用分屏（某分组 >1 个窗格）或 >1 个分组 → 开（老用户界面不突变）。**停靠面板开着不算**（裁决：旧版默认就开着，而且 Ctrl+J 一下就回来；用户本人就是开着停靠面板、想要简化界面的人）。`loadLayout()` 返回 `{layout, saved}` 就是为了这个。迁移到「关」的老用户（有保存的布局 / `onboarded` / 设过 `ui.singleWindow`，`needsSimplifiedNotice()`）弹一次 12 秒 toast「界面已简化；需要分屏 / 标签 / 面板图标栏可在 设置 → 通用 打开「显示工作台工具」」（`terms.ts` 的 `SIMPLIFIED_NOTICE`，路径在 `WORKBENCH_SETTING_PATH`，`settings/catalog.test.ts` 对照设置表断言），记 meta `ui.simplifiedNotice`，只弹一次；全新安装不弹。关着时分屏 / 分组 / 标签的快捷键照样能用（`commands.ts` 去掉了 single 拦截），`new`（Alt+N）在当前窗格原地换成新对话，开着时仍是新标签。**原地替换只换对话**（裁决 I3，学 Codex）：`tile.open` 的 `replace` 只在当前活动标签是对话时生效，前面是终端 / 文档 / diff / 浏览器就新开标签——终端进程不断、有未保存改动的文档不会绕过关闭确认；侧栏点会话、命令面板、通知点击（`setActive` / `openInPane(…,'replace')`）走的是同一个 reducer，一起修好了。被替换的对话还在侧栏，跑着的不停。`ui.singleWindow` 键留在 meta.json 里不删。
- **会话头一行（≤ 52px）**：`tiles/ChatTile.tsx` 的 `SessionHeader`：标题（双击改名）· 灰字「项目 · 分支（有未提交改动加 •）· 独立副本 · 非 Claude 的 agent 名 · 只读」（终审 I3：项目 / 分支是 `<span className="it">` 灰字，不是按钮——「在资源管理器打开」在 `···` 和命令面板里，未提交的改动看 +N −M / 右侧面板的审阅 / `···` 改动，tooltip 里写着），右侧「+N −M」（`model/diffstat.ts` 的 `sessionDiffStat()`：优先 `structuredPatch`，transcript 里没有 `tool_use_result` 时按 old/new_string 去掉公共首尾行估算）、终端、右侧面板（Ctrl+J；面板收成图标栏时这个按钮是「展开右侧面板」）、`···`。**手机上前三个不画**（spec §5.11：☰ · 标题 · ···），改动 / 终端 / 任务等都在 `···` 里，打开的是底部抽屉（阶段 7）。`···` 里「交给其它 Agent 继续」直接列出 agent（`SessionMenu` 的 `handoffInline`；侧栏菜单仍是二级展开），还有「本对话用量」（`data-act="usage"`，打开输入框那张统计卡，见「界面改版 阶段 3」）；已删除的对话也保留 `···`（`SessionMenu` 的 `deleted`：只剩导出、视图、打开目录、复制 ID）。`HeaderMenu` 只订阅置顶状态，动作在点击时读 store；`PaneEdgeContext` 的值用 `useMemo`。原来的 EngineSwitcher 删了：换档案在模型菜单，换 agent 在 `···` 的「交给其它 Agent 继续」。
- **8 个工作台标签的去处**（阶段 2 已搬进右侧面板，见下一节）：表在 `workbench/wb-views.ts` 的 `WB_VIEWS`，`···` 菜单（`HeaderMenu`，两列网格，`data-view`）和命令面板（`s.<view>`）都从它生成，`wb-views.test.ts` 断言每个 `WORKBENCH_TABS`（除 `live`）都在；原地打开的视图（只剩远端会话上的视图；定时任务是自动化页，手机上的视图进底部抽屉）在会话头显示一个可关闭的胶囊，点它回到对话。「对话 ⇄ 轨迹」改叫「步骤视图」（`···`、命令面板、Alt+J）。命令面板的视图命令和 Alt+J 作用在 `currentChatTile(layout)` 上：前面是文档 / 终端时找这个窗格（再是这个分组）里当前会话的对话标签，先切过去再换视图，不再静默无效。
- **右侧面板开关**：`panelToggleEffect(dock, id, workbench)` 说清楚一次开关会做什么——不在视野里（没开 / 在别的标签后面 / 收成图标栏）就 `show`；在视野里时，`PANELS` 里标了 `keepAlive` 的（终端：关标签会杀 pty）和默认界面的四个固定标签只 `hide` 整个面板，其它的 `remove` 标签（`workbench` 缺省 true = 改版前的规则；store 的 `togglePanel` 按 `ui.workbench` 传）。Ctrl+`、图标栏按钮、命令面板都走它，文案由 `terms.ts` 的 `panelToggleLabel()` 按效果生成（「隐藏终端面板（继续在后台运行）」）。
- **桌面标题栏**：没有全局顶栏，每一栏的第一行就是标题栏。`PaneLayer` 给每个窗格算它碰到的窗口边（`data-top` / `data-left` / `data-right`，分组栏在时没有窗格算 top），`.pane.tabs` 表示标签条显示中；CSS 在 `styles.css` 末尾「desktop title bar」一段：`.sb-top`、`.groupbar`、`.dock-tabs`、顶部窗格的第一行（标签条，没有标签条时是 `.sess-head` / `.welcome-top`）都是 `-webkit-app-region: drag`，里面的按钮 / 输入框 / 标签 no-drag；Windows / Linux 右上角那一行（停靠面板展开时是 `.dock:not(.min) .dock-tabs`）`padding-right: 150px`——**收成 36px 图标栏时不算 `dock-open`**（`App` 里 `rpWidth > 36`），系统按钮盖住的是工作台右上角那一行，所以由会话头 / 标签条 / 分组栏让位，图标栏自己 `padding-top: 40px`；标题、`.sh-meta` 里的项、带 `title` 的元素都是 no-drag（拖动区会吞掉双击改名和 tooltip）；mac 侧栏收起时左上角那一行 `padding-left: 84px`，那一行里的「展开侧栏」不再带 −8px 的左外边距（终审 M5：和侧栏顶行的按钮对齐）。`PaneEdgeContext`（`workbench/pane-edge.tsx`）把 `lead`（左上角那一行）/ `strip` 传给 tile，决定谁画「展开侧栏」。
- **踩过的坑**：
  - **侧栏收起时 grid 错位**（阶段 2 起就有）：收起时侧栏换成 `display:none` 的占位，不占 grid 格子，而 `--sb` 又被行内 style 盖住 `.app.no-sidebar{--sb:0}`，于是中栏滑进侧栏那一列（264px 宽）、停靠面板占了 1fr。现在 `.app.no-sidebar:not(.mobile)` 直接改成两列 `1fr var(--rp)`。
  - 分组栏以前 `overflow-x: auto`，里面的布局预设菜单会被裁掉；现在只有 `.gtabs` 滚动。
  - 单窗格时 `.pane` 没有边框 / 圆角 / 焦点色（`.pane-layer:not(.multi)`），分屏后才回来。
  - 欢迎页 textarea 自动聚焦会画 `:focus-visible` 橙框，`.composer textarea:focus-visible{outline:none}`（外框 `:focus-within` 已经表达了）。
  - **手机打不开侧栏**（审查 C1）：工作台模式下分组栏被 CSS 藏了，但 `chromeVisibility` 还当它在，于是没有窗格算 top、没有人画「展开侧栏」。外框在手机上要在 `chromeVisibility` 里关，别只靠 CSS 藏。
  - 侧栏里的浮层会被侧栏的 overflow 裁掉：`UsageRing` 的悬停框（`tip`，现在账户行传 `tip={false}`，明细在账户弹层里）portal 到 `body`、fixed 定位在锚点上方，侧栏菜单是 `position: fixed`（阶段 4）。
  - `shot.cjs` 截图时 JS 在应用初始化完成前就跑了，紧接着 `dispatchLayout` 的结果可能被覆盖（看到的尺寸 / 面板状态不对）；改布局的步骤包在 `setTimeout(…, 1500)` 里。ui-smoke 的离屏窗口 `setContentSize` 之后的截图也不可靠，只用来断言 DOM。
- **默认对话页静止时可点的外框控件：16 个**（spec §8 要求 ≤ 16；终审 I3 之前是 19，终审修复后 15，复审 M-6 让没有项目时的「其它文件夹」标题重新可折叠后 16；阶段 C 把漏斗换成「显示」按钮，一换一，仍是 16；「显示」按钮只在有东西被筛掉 / 显示已归档 / 关了「其它 agent 的对话」时亮点并常显，自己选的分组 / 排序 / 每组几条不亮——那是列表本身看得出来的设置，亮着就成了静止时多一个控件（阶段 C 修复 C-U4））。口径是终审探针的 `countCtl`：侧栏里对话行以外、会话头、输入框那一行里看得见（有尺寸、不透明、不在 `[hidden]` / `[inert]` 里）的 `button / [role=button] / [role=tab] / a[href] / input / select / textarea / [tabindex=0]`，嵌在按钮里的不重复算，指针不在侧栏上。场景：全新 HOME、没有项目、一个文件夹里有 CLI 的历史对话、从侧栏打开它（没在运行）。侧栏 7（新对话 · 搜索 · 自动化 ·「其它文件夹」标题 · 那个文件夹 · 账户 · 设置）+ 会话头 4（+N −M · 终端 · 右侧面板 · ···）+ 输入框 5（+ · 模型 · 权限 · 语音 · 发送）。省下来的：会话头的项目 / 分支是灰字、上下文小环 ≥ 60% 才出现（其余在 ··· 本对话用量）、收起侧栏和「项目」标题行的漏斗 / + 悬停或聚焦才出现、没有项目时不另画「打开文件夹」按钮、对话库发现提示等入门清单结束（或满 3 天）；多出来的是没在运行的对话的模型 / 权限 chip（终审 §9 #1）。每多一个项目 +1。
