# 桌面版（desktop/）

```
npm run desktop         # 编译 server/web/desktop 后用源码起 Electron
npm run build:desktop   # electron-builder → dist-desktop/ClaudeWeb-<ver>-win-x64.exe (NSIS) + ClaudeWeb-<ver>-portable.exe
```

- **窗口先开，server 后起**（2026-09-29）：`whenReady` 里先 `createWindow(null, 'main')` 显示一个 data: URL 的启动页（`splashUrl()`：主题色底 + 「正在启动…」，整页可拖动），`host.start()` 回来再 `loadURL` 真页面。以前窗口要等 server 起来（打包版 ~15 s）+ 页面 `ready-to-show` 才出现，这段时间再从开始菜单点一次，`second-instance` 找不到任何窗口可显示——用户看到的就是「打不开」。`--hidden`（开机自启）只作用于启动时建的那几个窗口（`createWindow` 的 `hidden` 参数；以前是建完再 `hide()`，但 `ready-to-show` 晚到又把它显示出来了）。
- 壳只做四件事：`utilityProcess.fork(server/dist/index.js)`（PORT=0 自选端口 + 随机 token）、BrowserWindow 加载 `http://127.0.0.1:<port>/?token=…`、托盘/菜单/通知、`window.desktop` 桥（preload）。
- **utilityProcess 里 `process.send` 不存在**，server 用 `process.parentPort.postMessage({type:'ready'})` 报告端口；别给它设 `ELECTRON_RUN_AS_NODE`（会让它拒绝 Chromium 参数直接退出）。
- 前端通过 `web/src/desktop.ts` 判断是否在桌面壳里：选目录 / 打开路径 / 通知 / 菜单快捷键都走桥，浏览器模式退回原逻辑。`html.desktop` 类让每一栏的第一行成为可拖动标题栏（没有全局顶栏了，规则见「界面改版 阶段 0–1」），右上角那一行留 150px 给系统窗口按钮。
- 打包后原生二进制在 `app.asar.unpacked`：`resolveClaudeExe()` 和 node-pty 加载都做了路径修正。
- 日志：`%APPDATA%\claude-web\server.log`、`main.log`。
- electron-builder 只打包**根 package.json 的 dependencies**（workspace 子包的不算），所以 server 的运行时依赖在根 package.json 里也列了一份；`npmRebuild: false`，node-pty 用自带 prebuilds（本机没有 VS Build Tools，rebuild 会失败）。
- 调试打包后的 server：设 `CLAUDE_WEB_TOKEN=xxx` 起 `electron .`，然后浏览器开 `http://127.0.0.1:<port>/?token=xxx`（端口看 server.log）。
- **安装包里的 sidecar**（2026-10-20）：`electron-builder.yml` 的 `extraResources` 把 `vendor/sidecars` 放到 `resources/sidecars/<平台>/<id>/`；打包时 `desktop/src/server-host.ts` 用 `CLAUDE_WEB_SIDECARS` 告诉 server。`scripts/sidecars/fetch.mjs` 按 `server/src/upstreams/sidecars.json` 下载、校验 SHA256、解压，CI 在打包前按矩阵平台跑；`vendor/sidecars/*` 不进 git。本机已经开着装好的应用时，`scripts/smoke-packaged.mjs` 起不来（`requestSingleInstanceLock`）；这时用 `ELECTRON_RUN_AS_NODE=1 "<安装目录>/Claude Web.exe" "<…>/resources/app.asar/server/dist/index.js"` 直接跑打包后的 server 验证，别去关用户的应用。
- **安装包里的 CLIProxyAPI / Magpie**（2026-10-28 用户要求）：同一条路。`scripts/engines/fetch.mjs` 按 `server/src/engines/manifests/bundled.json`（版本、平台 asset、SHA-256 都钉住）下载到 `vendor/engines/<平台>/<id>/`，`extraResources` 放到 `resources/engines`，`server-host.ts` 用 `CLAUDE_WEB_ENGINES` 传进去；`EngineManager` 优先用用户装过的 build，其次用随包的（`bundled: true`），都没有才联网装。`build:desktop*` / release workflow 都会先 fetch。`vendor/engines/*` 不进 git；`scripts/smoke-packaged.mjs` 会断言两个引擎都 `bundled` 并能真的启动、停止。**随包 build 不在 `uninstall` 里删**（它在应用资源里，删不掉），界面也不给「卸载」，只给「更新」。
- **应用自己的更新**（2026-09-30 用户要求：以前只有设置 → 高级 → 更新的按钮会去看，没人更新）：启动 15 s 后和每 4 小时检查一次（`flags.json` 的 `autoUpdate: false` 关掉，更新页有开关）。决定都在 `desktop/src/update-policy.ts`（纯函数，`update-policy.test.ts`，`npm test` 现在也跑 desktop）：`updateMode()` —— Windows 安装版（NSIS）是 `auto`（`autoDownload` + `autoInstallOnAppQuit`，下好后弹窗，「立即重启更新」= `quitAndInstall(true, true)` 静默安装再启动，「稍后」= 退出时自动装），macOS 能替换自己时也是 `auto`（见下一条「Mac 自己更新」），其它都是 `manual`：替换不了自己的 Mac 版、免安装版（`PORTABLE_EXECUTABLE_FILE`；它没有 `app-update.yml`，所以 `setFeedURL` 显式给 github，只检查不下载）、Linux——弹窗给这台机器的文件链接（`manualDownloadUrl()`：Rosetta 下的 x64 版给 arm64 dmg）。发布说明里写 **`【必须更新】`**（`REQUIRED_MARK`，要原样这几个字）的版本弹窗没有「稍后」、Esc 不关；它的自动下载失败时退回手动下载。`releaseNotes`（GitHub 给的是 HTML）由 `notesText()` 转成纯文本。前端 `web/src/features/update/`（`model.ts` 的 `promptFor` / `promptCopy` + 测试，`UpdatePrompt.tsx` 只在 main 窗口画，`.dialog-bg` 在设置页之上；「稍后」按版本记在内存里 24 h，重启再问）。每一步写进 `main.log`（`[update] checking / available x / downloading x / downloaded x / installing x / error …`）。**端到端**：`CW_UPDATE_FEED=<generic feed>` 换掉 GitHub、`CW_UPDATE_FIRST_MS` 缩短首次检查；`scripts/smoke-packaged.mjs` 起一个广告 99.0.0 的本地 feed，断言 Windows 安装版下到 `downloaded`、macOS 下到 `downloaded` 并解开了替身 app、Linux 只到 `available` 什么都不下（发版和手动触发的 Release workflow 都会跑）。用源码起（`electron .`）测下载要在仓库根放一个临时 `dev-app-update.yml`（`provider: generic`、`url`、`updaterCacheDirName`），测完删掉；别点「立即重启更新」（会运行 feed 里的假安装包）。**已经装了 v0.1.2 及更早版本的人要最后手动更新一次**，自动检查从带它的版本开始生效。更新日志在根目录 `CHANGELOG.md`（每个版本一节，发版时把「未发布」改成版本号）。
- **Mac 自己更新**（2026-10-18 用户要求：mac 手动更新太麻烦，不想花 99 美元做签名）：不走 Squirrel.Mac（它要新旧两个 app 都有 Apple 签名），自己换 `.app`。检查仍是 electron-updater（`latest-mac.yml`，`autoDownload` / `autoInstallOnAppQuit` 在 mac 上关掉）；`update-available` 时 `macZip()` 挑这台机器架构的 zip（Rosetta 下的 x64 版拿 arm64），`desktop/src/mac-update.ts` 用 `net.fetch`（走系统代理）下到 `<userData>/update/`、核 sha512 和大小、`ditto -x -k` 解到 `update/new/`、`plutil` 查 Info.plist 的 bundle id（`com.claude-web.desktop`）和版本、可执行文件在、`xattr -cr`，然后才报 `downloaded`（zip 删掉，解开的 app 留着；没装就重启的话下次直接复用）。「立即重启更新」/ 失败启动的「安装并重启」= `installAndRestart()`；「稍后」= `will-quit` 里装（`app.exit()` 的重启——GPU 回退、`desktop:relaunch`——不发 `will-quit`，不会在重启途中换 app）。安装是 detached 的 `/bin/sh update/swap.sh`（`MAC_SWAP_SCRIPT`）：等主进程 pid 退出（最多 120 s）→ 旧 app 挪到 `update/new/previous.app` → 新 app 挪到原位（失败就把旧的挪回来）→ `xattr -cr` → `open`；结果写 `update/result`（`ok <v>` / `fail <v> <原因>`），下次启动 `takeResult()` 读出来写进 main.log（`[update] installed x` / `installing x failed: …`）并清掉整个 `update/`；失败过的那个版本记在 `update-failed.json`（在 `update/` 外面，清理不会删掉；换成功一次就删），以后每次启动都给它手动下载（`mode: 'manual'` + `why`），不会反复下 200 MB 再被拒。**什么时候替换不了**（`macSelfUpdateBlocker()`，`mode` 一开始就是 `manual`，`why` 给前端）：源码起（`dev`，否则会换掉 node_modules 里的 Electron.app）、translocated（从「下载」或 dmg 直接打开，路径里有 `/AppTranslocation/`）、`.app` 或它所在的文件夹不可写（dmg 卷、普通用户的 /Applications）；`latest-mac.yml` 里没有这台机器的 zip（两个 mac job 互相覆盖、收尾没合并，见「macOS / CI」）也退回手动。**没在真 Mac 上跑过的**：macOS 13+ 的「App 管理」会不会拦未签名 app 挪自己（拦的话 mv 报 `Operation not permitted`，走上面的失败路径，提示里写了去哪儿允许）、换完后辅助功能 / 屏幕录制授权要不要重给（ad-hoc 签名每版不同，手动更新也一样）。swap 脚本在 POSIX 上有真跑的测试（`update-policy.test.ts`，Windows 上 skip），smoke 在 mac 上会走到 `downloaded`。**装着 0.2.9 及更早版本的 Mac 要最后手动更新一次。**
- **v0.2.7 打不开（2026-10-18）**：`yaml`（「从其它工具导入」用）只加进了 `server/package.json`，安装包里没有，server 一启动就 `ERR_MODULE_NOT_FOUND`。`smoke-packaged.mjs` 当时没拦住：它直接跑 `dist-desktop/win-unpacked`，Node 往上找包会找到仓库自己的 `node_modules`。现在：`server/src/app/packaging.test.ts` 查 server 的依赖和 server 源码里运行时 import 的包都在根 package.json 里；smoke 先把应用复制到临时目录再跑，并多跑一遍「server 起不来」（`CLAUDE_WEB_DIR` 指向一个文件）断言 Windows 安装版会去下新版本——`main.ts` 的 `updateInsteadOfFailing()`：启动失败时检查更新，下好了弹窗「安装并重启」，不再只报错退出（0.2.7 在 15 s 的首次检查之前就退了，没法自己更新出去）。查这类问题：用装好的 exe 直接跑 server，`ELECTRON_RUN_AS_NODE=1 "<安装目录>/Claude Web.exe" "<安装目录>/resources/app.asar/server/dist/index.js"`，报错会直接打出来（桌面版的 server.log 里只有 `server exited with 1`）。
- **「server did not become ready in 30s」（2026-10-25 用户报告：电脑 12 核跑满时崩过一次后，每次重开都报这个，重启电脑才好）**：server 没卡死，只是慢。热启动几秒（2.5 s 在加载模块），冷启动要第一次读几千个模块文件、杀毒软件逐个扫，CPU / 磁盘被占满时会拖过 30 s——作者机器上的 main.log 也有三次，server.log 显示 server 在 34 s、41 s 时就起来了，却已被固定 30 s 的超时判死、应用退出；这台机器 CPU 100% 时空 HOME 冷启动实测 110 s（热的、再加 12 个满负载进程也只要 5 s）。现在 `server-host.ts`：`SLOW_START_MS`（20 s）后发 `slow`，启动画面换成「电脑比较忙，启动得比平时慢，请稍等…」；只要进程还活着就等到 `START_TIMEOUT_MS`（180 s），到了才报错并 kill 掉那个 server（`server-host.test.ts` 用 `vi.mock('electron')` + 假定时器测）。真机验法：把 `server/dist/index.js` 临时换成先 `setTimeout` 45 s 再 `import('./index.real.js')` 的包装，`electron . --user-data-dir=<临时目录> --remote-debugging-port=…` 起开发版，轮询 `/json` 看页面地址（**Electron 在 Windows 上不看 `APPDATA` 环境变量**，不给 `--user-data-dir` 会撞上已装桌面版的单实例锁、一声不响地退出）。「运行中自己退出」不是这条：server 崩了壳会重启它并弹通知，整个应用退出只有 GPU 连崩两次的软件渲染重启（只一次）和主进程自己崩，要看用户的 `%APPDATA%\claude-web\main.log` / `server.log` 和 Windows 事件查看器。
- **右键菜单**（2026-10-20 用户要求：选中文字右键什么都没有）：Electron 不给页面任何默认右键菜单。`main.ts` 的 `attachContextMenu()` 挂在每个应用窗口和内置浏览器的每个 `<webview>` 页（`did-attach-webview`）上，菜单内容由纯函数 `desktop/src/context-menu.ts` 的 `menuItems(params)` 决定（`context-menu.test.ts`）：输入框里 剪切 / 复制 / 粘贴 / 删除 / 全选（按 `editFlags` 灰掉；拼写建议 / 添加到字典只在开了 spellcheck 时才有，应用窗口是关的）；输入框外有选中文字：复制 / 引用到输入框 / 全选；链接：复制链接；图片：复制图片；都不沾就不弹。编辑项直接调 `wc.copy()` 等，不用 role（role 作用于有焦点的那个 webContents，`<webview>` 时不一定是被点的那页）。「引用到输入框」发 `desktop:quoteSelection` → `App.tsx` → `features/composer/quote.ts` 的 `quoteInComposer()`（窗口事件 `cw:composer-quote`，聚焦分屏最前面那个标签的输入框接，右键的 mousedown 已经把分屏聚焦了），把选中文字作为 `> …` 引用加在已打的字后面；没有输入框接就 toast。**不会出两个菜单**：页面自己的菜单（文件树、标签、侧栏行…）对 DOM `contextmenu` 调了 `preventDefault()`，Chromium 就不向浏览器进程要菜单，Electron 根本不发 `context-menu`（Electron 44 上用探针页 + `sendInputEvent` 右键实测过），所以不需要和页面握手。

## 开场动画（2026-11-04，设计交付包 claude-web-opening）

- 启动页（`splashUrl()`）换成交付包的开场：`desktop/src/opening.ts` 生成一整页 data: URL（Logo SVG 原样内联，样式全在这页里，碰不到应用）。时间轴 / 五次 smoothstep / 字号 / 配色照包，去掉了预览用的重播按钮和 `window.__opening`；`prefers-reduced-motion` 直接终态。
- 包里没有的、我们加的：系统是暗色时用应用的暗底（`#12110f`，Web 变浅色，Logo 外一圈 1px 淡描边，否则黑方块融进背景）——避免暗色应用开机先闪一屏白；动画放完 3.5 s 还没进应用时下方淡出「正在启动…」；20 s 的「电脑比较忙…」改为 `executeJavaScript(setOpeningNote())` 只换那行字，不重载（重载会重播动画）。
- 速度：动画本身 1.45 s 没改。服务比动画先好时（热启动）等到开场页 dom-ready 后 1.6 s（`openingHold`）再换真页面；冷启动本来就更久，不多等。实测（开发版、临时目录）：冷启动开场 1.3 s 出现、14.9 s 进应用；热启动 1.1 s / 3.7 s。`--hidden` 启动不等。
- 截图办法：离屏窗口的 `capturePage()` 不回、挪到屏幕外报 UnknownVizError——用 `offscreen: true` + `paint` 事件拿最后一帧，并给脚本单独的 userData。
