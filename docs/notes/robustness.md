# 子进程窗口 / 前端健壮性（2026-09-28）

- **停止一定要停得下来**（2026-09-30 用户报告「一直思考中，点停止也停不了」）：
  - `SessionRunner.interrupt()`：CLI 正常会用一个 `result` 回应中断；`STOP_GRACE_MS`（8 s）内这一轮没结束（卡在一个永远不回的请求上，或者根本不读控制通道了），就自己发一个 `terminal_reason: 'aborted_forced'` 的 result（reducer / 账本 / 界面像普通中断一样收尾，前端归为「已中断」），再 `respawn()` 杀进程、在同一个对话上 resume。消息泵发现 `this.q` 被换掉就不再转发旧进程晚到的消息。
  - `session.interrupt` 找不到这个对话的进程（关了、崩了、服务重启过，而窗口还显示「运行中」）回 `{ running: false }`，不再抛「is not open」——以前前端的 onClick 没有 catch，停止按钮静默失败。前端 `store/stop.ts`：`running:false` 时用一个 `aborted_stale` 的本地 result 结束这一轮；其它错误 toast「停止失败」。
  - 用真 ccb + 假中转（`upstream.mjs`：永不回应 / 回完不发 `[DONE]` 也不断开）实测：这两种上游都会让界面一直「思考中」、一个字不出，但 ccb 都能正常响应中断；强制路径靠 `session-runner.test.ts` 的 mock（`interrupt()` 返回但永远不出 result）。
- **终端面板是 shell，不是 claude**（2026-09-30 用户报告）：以前 `TerminalService.open()` 直接起自带的 `claude` TUI——它启动时先连 api.anthropic.com，国内直连 403 就「进程退出 1」，只用中转、没有 Claude 账号的人终端完全不能用；而且「安装 / 登录 agent」、git init、配置 git 身份这些按钮敲进去的 shell 命令会被 Claude 当成一句提示词。现在 `terminal/service.ts` 的 `terminalShell()`：Windows 是 `ComSpec`（cmd.exe——PowerShell 默认执行策略拒绝 npm.ps1，`npm i -g` 会失败），macOS / Linux 是 `$SHELL -l`；自带 claude 的目录追加到 PATH 末尾（用户自己装的 claude 优先；Windows 上沿用原来的 `Path` 键，不另加一个 `PATH`）。登录入口运行 `claude auth login`（`AGENT_DEFS` 的 claude.login 同）。对话本身不受影响：走中转的对话由 ccb 驱动，不做这个 403 预检。
- **本机地址绕开系统代理**：缓存垫片 / 模型网关在 127.0.0.1，而 ccb 的 API 请求认 `HTTP(S)_PROXY`——用户环境里有代理（国内常见）时，发往本机的请求也会被交给代理：死代理立刻「API Error: Connection error.」，全局模式的真代理把它转去远端节点就一直挂着。runner 在 env 里的 `*_BASE_URL` 是回环地址时，用 `providers/service.ts` 的 `loopbackNoProxy()` 给 `NO_PROXY` / `no_proxy` 补上 `127.0.0.1,localhost,::1`（保留用户原有的）。实测：`HTTP(S)_PROXY=http://127.0.0.1:9` 下修复前中转一个请求都没收到，修复后正常回答。

- **桌面版一直弹 PowerShell / cmd 窗口**：server 跑在 Electron utilityProcess 里，ccb、npm 垫片的 agent（gemini / opencode / codex 的 JS 入口）跑在 Electron-as-node 里——Electron 是 GUI 子系统程序，**这些进程都没有控制台**，它们起的任何控制台程序（git、reg、cmd、powershell、where…）只要没带 `windowsHide` 就各开一个可见窗口。我们自己的调用早就带了；弹窗来自子进程自己的 spawn：ccb 周期性 `reg query HKLM/HKCU\SOFTWARE\Policies\ClaudeCode`、`where.exe`、`git`，opencode 的 `--version` 每次 4 个 PowerShell/pwsh AVX 检测（版本探测一被触发就是一串 PowerShell 窗口）。真 `node.exe` 是控制台程序，`windowsHide` 给它一个隐藏控制台，孙进程继承，所以网页版（`npm start`）不弹。
- **修法 = spawn guard**（`server/src/runtime/spawn-guard.ts`）：一份 CommonJS 源码，两处运行——server 进程内（`index.ts` 的**第一个 import** `runtime/spawn-guard-install.ts`，ESM 按 import 顺序求值，后面模块在加载时 `promisify(execFile)` 拿到的也是补过的）；Electron-as-node 子进程里作为 `--require` 预加载（写到 `<dataDir>/runtime/spawn-guard-<hash>.cjs`，不放 src/ 是因为 tsx、tsc 产物、asar 三种布局下都要是磁盘上的纯 JS；`nodeRuntime().args` 统一加，`spawnClaude` / `runClaudeCli` / `resolveSpawn` 的 node-shim 都走它）。补丁把 child_process 的 spawn/exec/execFile/fork 及 Sync 版的 `windowsHide` 缺省成 true（显式 `false` 保留），保留 `util.promisify.custom`，再 `syncBuiltinESMExports()` 让 ESM 具名导入也生效（ccb 是 ESM）。预加载文件复用前比对大小 + sha256，不一致就重写，写不进去返回 null 并清掉 `.tmp`；`guardNodeArgs()` 先试 `<dataDir>/runtime`、再试 `os.tmpdir()/claude-web-runtime`，都不行子进程不带 guard 照常启动，进程内只 `console.warn` 一次（进 server.log）。`spawn-guard.electron.test.ts` 用真 Electron（`ELECTRON_RUN_AS_NODE=1`）跑 ESM 脚本验证注入，没有能启动的 Electron 就 skip。新写的调用仍然要显式写 `windowsHide: true`。

  - **点击助手是带守卫的真实点击**（统一打磨 P5）：`click(selector)` 先滚进视野，再**等目标的框在连续几帧里不动**（页面内 rAF 比较，最多 90 帧 / 2 s），然后在页面里挂一次性的 `mousedown` 守卫、再发真实鼠标事件；落点不在目标里的 mousedown 连同它的 mouseup / click 一起被吞掉（不会误点到别的开关）并记进日志（`landed on …`），然后重新量、重新点（最多 4 次）。**偶发失败的两个原因**（「设置 · 通用 / 账号与登录 / 手机与其它电脑 › 更多选项」没展开）：① **设置页换页后隔一帧才滚回顶部**（`SettingsPage` 的 `[target]` effect 以前包在 `requestAnimationFrame` 里）：通用的「更多选项」在首屏以下，助手刚把它 `scrollIntoView` 到中间，那一帧的 `scrollTop = 0` 就把它甩回窗口外（守卫的自检实测抓到过：第一次量到 y=1047，落点是 `<html>`）；现在改成 `useLayoutEffect`，在显示新页的那次提交里、绘制前滚好，用户换页后马上滚轮也不会被拉回去。② **页面自己的请求回来把目标挪走**：坐标在页面里量好、输入事件几毫秒后才异步到达——账号与登录在登录检查回来时长高约 66px（服务端缓存 30 s 过期后再进这页就是 2～3 秒后）、手机与其它电脑在远程 / 机器状态到达时长高约 200px（服务端忙时更晚）；旧助手量了四次都不中也照点，点到别处。设置阶段开头有一条自检：在量完之后用 `transform` 把页面内容往下推 44px（按钮上面那一行落到点击点上；别用改 `padding` 的办法——滚动容器的 scroll anchoring 会把位移抵消掉，自检就什么也没测到），断言那一下被吞掉、通用页的开关一个没变、第二次点中。所以别再加 `sleep` 等页面稳定，用这个助手；`更多选项` 没展开时日志里有按钮每帧的位置（`trail`）、当时的 toast 和那一点上的元素。
  - 截图 `ux-*.png` 和 `ui-smoke.json` 在 `--out`（默认 `%TEMP%\cw-ui-smoke`）。选项全走 env 传给 Electron（argv 带冒号会被当 URL），默认离屏渲染（`--show` 才弹窗口）；`ELECTRON_DISABLE_SECURITY_WARNINGS` 关掉 Electron 的开发期 CSP 提示（打包后本来就没有）。`--url "<带 token 的地址>"` 可以对已经在跑的 server 做只读检查（不打字存草稿、不开终端面板、不改 onboarded、不跑崩溃探针）。

## 2026-10-24：回答里的链接 / 主窗口白屏 / 菜单被裁（stage A 的 A1、A2，spec `2026-10-24-desktop-parity-design.md`）

- **A1 现象**：mac 上点回答里的文件链接，整个窗口变白。**根因**：`Markdown.tsx` 只拦 `http(s):`，`file://`、本地路径、相对路径落到 Electron 默认行为（主窗口导航走了）；`desktop/src/main.ts` 没有 `did-fail-load` / `render-process-gone` 恢复。**做法**：① 回答里所有链接走 `web/src/features/chat/link-route.ts` 的 `routeLink(href, cwd)` → `followLink`（http(s) 出去、文件 / 本地路径在应用里开、`#` 锚点照常、`javascript:` / `data:` 不开）；**网络路径一律不开**（`//host`、`\\host`、`/\host`、`file://host/…`：以前会经服务端 `fs.stat` 去连 SMB，Windows 会把 NTLM 凭据送过去）。② `desktop/src/nav-guard.ts`：主窗口只能停在应用页（同源且路径 `/` 或 `/index.html`，查询串不管），别的导航一律 `preventDefault`；`CrashGuard`：渲染进程崩 / 主 frame 加载失败 → 重载应用页、toast「页面出错，已恢复」（在 `web/src/boot.tsx`，**不在 `main.tsx`**：`main.tsx` 不能 import store，见 i18n 笔记），60 秒内第 3 次 → 停在说明页「页面连续出错」+「重新加载」，停下后不再自动重载（以前说明页的渲染进程再崩会无限循环）；应用页再次加载成功就清零。**验证**：`link-route.test.ts`、`nav-guard.test.ts`；Windows 上真桌面版（临时 HOME / `--user-data-dir`）经 CDP：`location.assign` 到 `file:///…` 和 `/draft-preview.html` 都留在应用页，杀三次渲染进程 → 两次恢复 + 说明页，点「重新加载」回来。**没有 Mac**，mac 只这样间接验过。ui-smoke 用的是普通 BrowserWindow，不走 `main.ts`，所以 A1 不在 ui-smoke 里。
  - **总审查 I1（2026-10-24）**：`file:///…`、`C:/…`、`C:\…`、`tel:` 的链接点了没反应。**根因**：react-markdown 的 `defaultUrlTransform` 只留 http(s) / irc / mailto / xmpp / 相对地址，别的 href 在到 `a` 组件之前就被清成 `''`（`C:/x` 被当成 scheme `C`；`C:\x` 先被 mdast-util-to-hast 编码成 `C:%5Cx`）。**做法**：`Markdown.tsx` 传 `urlTransform`：`href` 是 `file:` / `tel:` / `X:` 开头的原样放过，其余（含所有 `src`）照默认；`routeLink` 仍是唯一的安全闸，DRIVE 和 UNC 都对**解码后**的 href 判（`C:%5Cwork` 认得，`%5C%5Chost` 不开）。**验证**：`markdown-links.test.ts` 用 `react-dom/server` 渲真的 `<Markdown>` 取 href 再喂 `routeLink`；ui-smoke `parity-a`：种好的回答里一个 `file:///` 链接、一个 `C:\` 链接 href 都不空，点前者开出文档标签、`location.href` 不变（这段只查页面这边，不查 `main.ts`）。
  - **总审查 I2（2026-10-24）**：中键点回答里的路径链接还是开出一个空白窗口。**根因**：`main.ts` 的 `setWindowOpenHandler` 只看同源（`target.startsWith(origin)`），`http://127.0.0.1:3090/C:/Users/a/x.html` 也算。**做法**：`nav-guard.ts` 的 `windowOpenAction(target, appUrl)`：应用页本身（`allowNavigation` 为真，浏览器那条路 `workbench/windows.ts` 的 `window.open(?win=…)`）→ 开窗；同源的别的地址 → 什么都不开；别的 http(s) → 系统浏览器；其余不开。桌面版的「新窗口」走 IPC `desktop:window:new`，不经这里。`Markdown.tsx` 的 `a` 加 `onAuxClick`（只管中键 `button === 1`），和左键一样 `preventDefault` + `routeLink` / `followLink`（`linkHandlers`）。**验证**：`nav-guard.test.ts` 的 `windowOpenAction`、`markdown-links.test.ts` 的中键例子。
  - **总审查 M1（2026-10-24）**：`x.ts#L12-L20`、`x.md#section`、`page.html?v=1` 留在路径里 → 「找不到」的标签。`link-route.ts` 的 `cut()`：`#L12` / `#L12-L20` / `#L12-20` 取第一行，别的 `#…` 和 `?…` 从**本地路径**上切掉（web 地址不动）；在还没解码的 href 上切，`%23` 仍是文件名里的 `#`。
- **A2 现象**：侧栏行的 ··· 菜单顶部被「新对话」挡住、切掉（用户截图）。**根因**：菜单是就地画的 `position: fixed` 元素，在 `.sb-list` 里；滚动渐隐的 `mask-image`（`styles/scroll-fade.css`）**会把所有后代、包括 fixed 的，裁到这个元素的框里**——列表不滚时 mask 也在（渐变全不透明，但裁剪照样）。**做法**：`scroll-fade.css` 同一组 12 个列表加 `:has(.menu)` 时 `mask-image: none`（只改 mask，不碰 animation）；`useAnchoredMenu`（`features/sidebar/menus.tsx`）钉到顶时补 `overflow-y: auto` + `overscroll-behavior: contain`，重新定位时保留菜单自己的 `scrollTop`（侧栏里任何 DOM 变化都会触发重新定位，以前一变就弹回顶部）。**验证**：`place.test.ts` 加矮窗口例子；ui-smoke `parity-a` 段：窗口 600px 高、打开一行的 ···，断言第一项、最后一项用 `elementFromPoint` 点得到，`.sb-list` 的 computed `mask-image` 是 `none`，关掉后渐变回来。**坑**：mask 裁 fixed 的后代（overflow 裁不到 fixed 元素，mask / clip-path / filter 这类会）；`elementFromPoint` 不保证反映 mask 的裁剪，所以 ui-smoke 另外断言 computed `mask-image`，不只靠「点得到」。
- **EMFILE: too many open files（2026-10-30 用户截图：快速添加供应商时 `open '…\.claude-web\meta.json.<pid>.tmp'`）**：meta.json 只是下一个要开的文件，真正的原因是**服务进程的文件句柄漏光了**。`AgentTranscripts` 的 `headOf` 和 `CanonicalLog.head` 用 `readline` + `createReadStream` 读第一行后 `rl.close()` + return——readline 关了，底下的文件流只是暂停，句柄永远不关；`head()` 每次列对话 / 打开对话都跑，Windows 一个进程最多 8189 个，用满后所有 open 都 EMFILE（`.probe` 脚本实测第 8189 次失败）。改成 `runtime/first-line.ts` 的 `firstLine()`（`fs.open` 分块读、`finally` 关）。**别再用 readline 读一部分就退出**；读到底的循环没事（流结束会关）。`first-line.test.ts` 连调 9000 次。用户那边重启应用就能先恢复。

## 工具的输入不是工具要的样子，整个对话崩掉（2026-11-14 用户报告：「TypeError: e.questions?.map is not a function」）

  `util.ts` 的摘要都走它。
