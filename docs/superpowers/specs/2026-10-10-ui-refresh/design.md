# 界面翻新（2026-10-10）

样机：`mockup.html`（同目录；线上版 https://claude.ai/code/artifact/835feffb-29d5-46b1-9037-4838c43eb4c3 ）。
样机是用来定方向的，个别数值（比如权限卡和手机输入框的圆角）和本文不一样，以本文为准。
调研：`research/01`–`05`。本文里的数值凡是没有另外说明的，都来自这五份报告，报告里标了哪些是核实过的、哪些是推断。

## 1. 目标

用户的原话：现在的界面「有点四四方方」，要大改；字体更好看，颜色做好，图标完美，形状刚刚好；要更多交互；手机端要很方便。

做完之后应该是这样：

- 首页、对话、手机三个画面和已批准的样机一致。
- 功能一个不少，现有入口都还找得到。
- 现有的单元测试、端到端检查、界面冒烟全部通过（涉及尺寸的断言跟着改，行为断言不放宽）。

## 2. 「四四方方」的来源

| 现状（都在 `web/src/styles.css` / `ui/icons.tsx` 里数过） | 数字 |
| --- | --- |
| 实线 1px 描边 | 177 处 |
| 圆角用量 | 8px 70 处、10px 44 处、4px 29 处；22px 只有 5 处 |
| 图标 | 约 100 个手绘，24 网格 1.75 描边，矩形类是直角路径；用了 423 处 |
| 字体 | 字体栈第一位是 Inter，但没有任何 `@font-face`，实际是 Segoe UI + 微软雅黑 |
| `font-weight: 500` | 32 处（微软雅黑没有这个字重，对中文无效） |
| 动效 | 20 万字节的样式表里 8 个关键帧 |
| 布局 | 侧栏、对话、右侧面板是贴边的平面，靠线分隔 |

调研里三路独立得出同一个结论：光把圆角调大没有用，「方」主要来自贴边的平面和实线。

## 4. 设计语言

### 4.1 颜色

原色（替换 `:root` 和 `:root[data-theme='light']` 两个块）：

| 令牌 | 亮 | 暗 |
| --- | --- | --- |
| `--bg`（主面板、卡片内） | `#fefdfc` | `#1b1a18` |
| `--bg-1`（外壳底、侧栏） | `#f7f6f2` | `#12110f` |
| `--bg-2` | `#f0eeea` | `#252321` |
| `--bg-3` | `#e6e4df` | `#302f2c` |
| `--bg-elev`（菜单、输入框） | `#ffffff` | `#272623` |
| `--fg` / `-1` / `-2` / `-3` | `#1c1917` / `#47433f` / `#67625f` / `#7f7b77` | `#eeedea` / `#c4c2be` / `#a5a39e` / `#868480` |
| `--accent` | `#eb7f3b` | `#f5914f` |
| `--accent-text`（新增：橙色的字、焦点环） | `#a94900` | `#f9a56e` |
| `--accent-fg`（橙色底上的字） | `#1c1917` | `#1b1a18` |
| `--primary` / `--primary-fg` | `#1c1917` / `#fefdfc` | `#eeedea` / `#1b1a18` |
| `--user-bg` | `#f0eeea` | `#252321` |
| `--green` / `--red` / `--yellow` / `--blue` | `#12773d` / `#be2a27` / `#8a5d0b` / `#1c63bf` | `#69d98d` / `#ff8179` / `#f0c464` / `#80b6fb` |
| `--shade` | `40, 30, 20` | `0, 0, 0` |

已经算过的对比度（WCAG）：

- `--accent-text` 亮 `#a94900`：在 `--bg` / `--bg-1` / `--bg-2` / `--bg-elev` 上是 5.68 / 5.33 / 4.98 / 5.77。暗 `#f9a56e`：8.81 / 9.56 / 7.93 / 7.66。
- 墨色字压在亮橙上 6.36，压在暗色的橙上 7.49。白字压在亮橙上只有 2.75，所以橙色底上的字一律用 `--accent-fg`。
- 亮橙本身在白底上只有 2.7，不能当字用，也不够当焦点环。

规则：

- 语义层照旧由原色经 `color-mix(in oklab, var(--fg) N%, transparent)` 派生。描边 = 墨色 6% / 10% / 16%（暗色 7% / 11% / 18%）；悬停 / 选中 / 按下 = 墨色 5% / 8% / 12%。
- 橙色只出现在：品牌标记、焦点环、运行中的光点和流光、选中的勾、头像底色。橙色的字用 `--accent-text`。
- 焦点环改成 `2px solid var(--accent-text)`，不再用半透明的 `--accent`。
- 主按钮、发送键、开关的「开」仍是墨色。黄色只给「需要你」。
- 另外四个主题各补一个 `--accent-text`：它们的 `--accent` 在自己的四种底上够 4.5 就直接等于 `--accent`，不够就另取一个值。
- diff 的行底色从状态色混出来，六个主题自动跟着走：新增行 `color-mix(in oklab, var(--green) 13%, transparent)`，删除行 `color-mix(in oklab, var(--red) 11%, transparent)`。
- 语法高亮六个色放在同一个明度和色度上，只换色相（报告 05 §2.4 的表）。
- 半透明加模糊只给固定位置的浮层，全应用同时不超过三个元素。不用大面积渐变和发光描边。

`contrast.test.ts` 新增：两套默认主题里 `--accent-text` 在四种底上 ≥ 4.5，`--accent-fg` 在 `--accent` 上 ≥ 4.5；六个主题里 `--accent-text` 在 `--bg` 上 ≥ 4.5。`theme-preview.ts` 的色块表跟着换。

### 4.2 字体

```css
--font-cjk: 'PingFang SC', 'Microsoft YaHei UI', 'Microsoft YaHei', 'Noto Sans SC', 'Noto Sans CJK SC', 'Source Han Sans SC';
--font: 'Inter Variable', -apple-system, 'Segoe UI Variable Text', 'Segoe UI', var(--font-cjk), system-ui, sans-serif;
--mono: 'JetBrains Mono Variable', 'Cascadia Code', 'SF Mono', Menlo, Consolas, var(--font-cjk), monospace;
--display: 'CW Heading', 'Songti SC', 'SimSun', var(--font);
```

- 打包 Inter Variable（正体、斜体，带 opsz 轴）和 JetBrains Mono Variable，合计约 0.8 MB，带上各自的 `OFL.txt`。按 unicode-range 分片，手机走慢速转发时只取用到的那几片；每片都远小于转发的 2 MiB 上限。
- 正文中文不打包字体，用系统的。拉丁字体排在中文字体前面。
- `CW Heading` 是思源宋体 600 字重按用到的字裁出来的一个 woff2，连同它的字表一起提交进仓库。用它的只有：首页问候语、设置各页的页名、自动化页的页名、首次引导两步的标题。对话标题这类用户内容永远不用它。
  - 裁剪脚本在 `scripts/` 下，输入是上面这些字符串，输出 woff2 和字表。
  - 测试：这些字符串里的每个字都在字表里。有人改了页名而没有重新裁剪，测试会失败。
- 字号全是整数：

| 令牌 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--fs-micro` | 11 / 14 | 只给拉丁字母和数字 |
| `--fs-meta` | 12 / 16 | 时间、分区标签；中文的下限 |
| `--fs-sm` | 13 / 18 | 芯片、步骤行、侧栏对话行 |
| `--fs-base` | 14 / 20 | 列表、面板、控件 |
| `--fs-body` | 15 / 26 | 对话正文；手机 16 / 28 |
| `--fs-lg` | 16 / 24 | 卡片标题 |
| `--fs-xl` | 20 / 28 | 面板和对话框的标题 |
| `--fs-title` | 24 / 32 | 设置、自动化、首次引导的页名（用 `--display`） |
| `--fs-display` | 31 / 40 | 首页问候语（用 `--display`）；手机 26 / 34 |
| `--fs-code` | 13 / 20 | 代码 |

- 带中文的文字只用 400 和 600 两个字重，层级优先靠颜色（`--ink-1` 对 `--ink-2`）。现有的 32 处 500 逐个改成 400 或 600；500 只留给纯拉丁 / 数字的元素。
- `font-feature-settings: 'cv11', 'ss03', 'calt'`；`font-synthesis-weight: none`（不合成假粗体；斜体保持默认，中文的强调仍然倾斜显示）；`text-autospace: normal`（中英文之间自动留空，不支持的浏览器忽略）；数字列 `tabular-nums`；代码关连字。
- 手机上所有输入框字号 16px（iOS 小于 16 会自动放大页面）。

### 4.3 形状

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--r-xs` | 4 | 行内标记、键帽 |
| `--r-sm` | 6 | 小徽标、复选框、行内代码 |
| `--r-row` | 8 | 侧栏行、菜单项、列表行 |
| `--r-md` | 10 | 图标按钮、输入框、小卡片里的行 |
| `--r-lg` | 12 | 代码块、文件卡、菜单里的分组 |
| `--r-xl` | 16 | 卡片、主面板、右侧面板、菜单 |
| `--r-bubble` | 20 | 用户消息气泡（靠自己一侧的下角用 `--r-sm`） |
| `--r-2xl` | 24 | 输入框、权限卡、对话框、抽屉上沿 |
| `--r-pill` | 999 | 芯片、分段控件、文字按钮、圆形按钮 |

- 嵌套：内圆角 = 外圆角 − 内边距，不小于 4。
- 浮起来的东西不写 `border`，用阴影环：

```css
--elev-1: 0 0 0 1px var(--edge-subtle), 0 1px 2px rgb(var(--shade) / calc(.05 * var(--shade-a)));
--elev-2: 0 0 0 1px var(--edge-default), 0 4px 12px -2px rgb(var(--shade) / calc(.09 * var(--shade-a))), 0 14px 36px -10px rgb(var(--shade) / calc(.14 * var(--shade-a)));
--elev-composer: 0 0 0 1px var(--edge-default), 0 2px 4px rgb(var(--shade) / calc(.04 * var(--shade-a))), 0 12px 28px -12px rgb(var(--shade) / calc(.16 * var(--shade-a)));
```

  `--shade-a` 亮色 1、暗色 3。`--elev-3`（对话框）在 `--elev-2` 上再加一层更远的投影。

- 分隔优先用底色差和留白，其次用不贴边的细线。目标：实线 1px 描边从 177 处降到 60 处以内（阶段 3 结束时数）。样式表里不再出现令牌以外的圆角值。
- 文字按钮和主按钮是药丸形；图标按钮是 10px 圆角的方块；输入框里的「+」和发送键是正圆。
- 桌面增强：`@supports (corner-shape: superellipse(1.3))` 里给输入框、主面板卡片、对话框、菜单加 `corner-shape: superellipse(1.3)`，圆角相应放大 15%。阶段 1 截图时逐个看；阴影环或裁剪有瑕疵的那一类不启用，并把结果记在本文末尾。

**外壳。** `.app` 的底色是 `--bg-1`，四周留缝 `--shell-gap`：

| 情况 | 缝 | 卡片圆角 |
| --- | --- | --- |
| 桌面、舒适密度 | 8px | 16 |
| 紧凑密度（`ui.density`） | 4px | 12 |
| 手机（≤ 760px） | 0，主区域铺满，没有卡片 | — |

- 侧栏直接坐在外壳底色上，没有自己的边线和底色。
- 主区域是卡片：`--bg` + `--elev-1`。分屏时每个窗格各是一张卡片，缝就是分隔，拖动条在缝里。
- 右侧面板也是一张卡片。收成 36px 图标栏时坐在外壳底色上，不是卡片。
- 分组栏（出现时）在外壳底色上，卡片在它下面。
- 设置页、自动化页盖上来时用同样的结构：左栏在外壳底色上，内容是卡片。

**桌面标题栏。** 现在每一栏的第一行就是标题栏，这一点不变；外壳上边那条缝也算拖动区。Windows / Linux 右上角的系统按钮：

- 首选：`titleBarOverlay` 的底色用全透明的值，按钮浮在右上角那张卡片的头部行上，那一行继续让出 150px。
- 如果实测透明底不生效（先在 Windows 上验；Linux 没条件验，默认按不生效处理）：按钮区域用卡片底色 `--bg`，右上角那张卡片的上边和右边不留缝、右上角不做圆角。
- macOS 的红绿灯在侧栏那一列，位置规则不变。

### 4.4 图标

- 几何取自 Lucide（ISC 许可）。`lucide-static` 作为开发依赖；`scripts/gen-icons.mjs` 按一张「我们的图标名 → Lucide 名」的对照表，把 SVG 里的 rect / circle / line / polyline 转成路径，生成 `web/src/ui/icons.generated.ts`。运行时不依赖 Lucide。
- 品牌标记和六个 Agent 的标志（claude / codex / gemini / qwen / kimi / opencode）保留手绘，留在 `icons.tsx`。
- `Icon` 的用法不变（`name`、`size`）。线宽按尺寸算：≤ 20px 时渲染出来是 1.5px（`strokeWidth = 36 / size`），≥ 24px 时 1.75。圆头圆角。
- 尺寸：行内 16，工具栏和手机按钮 18，空状态 24–32。点击区不小于 28（手机 44）。
- 颜色：默认 `--ink-3`，悬停和选中 `--ink-1`。
- 实心版只给有「选中」含义的几个：置顶、收藏星、好评、差评。由同一个脚本从闭合路径生成。
- 测试：对照表里的每个 Lucide 名在装着的版本里存在；重新生成的结果和提交的文件一致；旧图标名一个不少（423 处用法不用改）。
- README 的「许可证与致谢」加上 Lucide、Inter、JetBrains Mono、思源宋体。

### 4.5 动效

```css
--dur-instant: 80ms; --dur-fast: 120ms; --dur-base: 180ms; --dur-slow: 240ms; --dur-slower: 320ms; --dur-page: 480ms;
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--ease-in: cubic-bezier(0.4, 0, 1, 1);
--ease-sheet: cubic-bezier(0.32, 0.72, 0, 1);
--ease-pop: cubic-bezier(0.34, 1.4, 0.64, 1);
```

| 场景 | 动什么 | 时长 / 曲线 |
| --- | --- | --- |
| 悬停底色 | background | 进 0，出 150ms |
| 按下 | `scale(0.96)`（手机 0.98） | 80ms，缓出 |
| 菜单、浮层 | opacity + `scale(0.96 → 1)`，原点在锚点 | 进 180ms 缓出，出 120ms |
| 对话框 | opacity + `scale(0.96)`；背板淡入 | 进 200ms，出 120ms |
| 折叠 / 展开 | 网格行 `1fr ⇄ 0fr` + opacity | 340ms，sheet 曲线 |
| 面板、抽屉、sheet | transform | 进 260–460ms sheet 曲线，出 150–220ms |
| 分段控件滑块 | transform | 260ms，sheet 曲线 |
| 流式文字 | opacity + `blur(3px)` | 240ms，只包新增的那一段 |
| 状态文字扫光 | background-position | 2.2s 线性循环 |
| 输入框流光 | 角度渐变转一圈 | 3.2s 线性循环 |
| 步骤进场 | opacity + `blur(5px)` + 上移 8px | 380ms，缓出 |
| toast | translateY + scale | 进 360ms pop 曲线，出 200ms |

规则：

- 只动 `transform`、`opacity`、`filter`、颜色。高度用网格行。不对列宽、外边距做过渡，不写 `transition: all`。
- 颜色和透明度不回弹，位置和大小可以。
- 键盘触发的操作不加进场动画。动画可以被下一次输入打断。
- 循环动画（扫光、流光、转圈、光点）只在所在的对话看得见、而且真的在运行时播放。
- 「减少动态效果」（设置里的开关，或系统的 `prefers-reduced-motion`）：保留颜色和透明度的过渡（不超过 120ms），去掉位移、缩放、模糊和循环动画；扫光的文字换成静态的 `--ink-2`。现在的做法是把时长全归零，改成这条。
- 旧的 `--dur-1..4`、`--r-*` 旧值、`--radius`、`--shadow` 在阶段 1 作为别名保留，阶段 3 结束时删掉。

## 5. 阶段 1 · 地基

做完后整个应用换了观感，交互还是老的。

1. 令牌拆到 `web/src/tokens.css`（原色、派生、圆角、阴影、字号、动效），`styles.css` 引它。写入 4.1–4.5 的值。
2. 字体：打包 Inter 和 JetBrains Mono，`@font-face` 用 `font-display: swap`；裁出 `CW Heading`；字号改整数；32 处 500 逐个改。
3. 图标：生成脚本、对照表、新的图标文件；`Icon` 的线宽规则。
4. 外壳：`.app` 的缝、主区域 / 窗格 / 右侧面板卡片化、侧栏去边线；`App.tsx` 里标题栏按钮颜色的逻辑和 `desktop/src/main.ts` 的 `titleBarOverlay` 按 4.3 改。
5. 全局基础件换到新令牌（颜色、圆角、焦点环）：`.btn`、`.icon-btn`、`.chip`、输入框、开关、滚动条、选区。它们的尺寸和结构留到阶段 3。
6. 另外四个主题补 `--accent-text`，逐个截图看。
7. 测试：`contrast.test.ts` 新规则、`theme-preview` 的色块、图标和标题字的测试；界面冒烟里因为缝和圆角变了的尺寸断言（`tab-row.ts` 的常数、右侧面板 1440 / 1024 两组数字）重新量。

这个阶段不动任何组件的行为和结构，除了 4 里列的外壳。

## 6. 阶段 2 · 对话与输入框

每一项都是「什么时候 → 怎么动 → 停在哪」。行为逻辑（发送、排队、插话、权限卡的回车语义和 600ms 冷却、折叠规则、摘要怎么数）一律不动，只换外观和过渡；例外单独写明。

| 部件 | 表现 | 落点 |
| --- | --- | --- |
| 输入框 | 圆角 24，`--elev-composer`，没有实线边。聚焦时环加深，外面多一圈 4px 的 14% 橙色光晕，180ms。两行：上面文字，下面控件。芯片没有边，悬停才有底色。 | `composer/ComposerBar.tsx` |

## 10. 约束与风险

- **界面冒烟里的尺寸断言。** 会话头 ≤ 52px 保持不变。右侧面板标签行的那组数字（`tab-row.ts` 的常数，1440 / 1024 两个场景）、目标标题行高度、手机抽屉高度会变，哪个阶段动到就在那个阶段重新量、同一次提交里改。只改尺寸常数，不放宽行为断言。
- **Windows 标题栏透明底**没有验过，见 4.3 的退路。
- **手机壳的入口文件上限**（每个入口文件 < 1 900 000 字节）：字体是单独的文件，不进入口；图标表会变大一点。每个阶段结束跑一次 `shell/assets.test.ts`。
- **性能**：循环动画只在可见且运行中时播放；带模糊的半透明浮层不超过三个；流式文字的包装只在流的过程中存在。
- **Safari**：`corner-shape`、`text-autospace` 会被忽略，不影响功能；高度动画一律用网格行，不用 `interpolate-size`；`@property`（流光）要 Safari 16.4，再老的版本只是没有流光。
- **验不了的**：没有 iPhone、Mac 和 Android 真机。阶段 4 里的 iOS 键盘、安全区、手势、Android 的触感，以及 macOS 桌面版的外壳，只能在 Chromium 的手机模拟下验，交付时逐条标明「没在真机上验过」，由用户拿设备试。

### 阶段 2

- 新规则按面分文件，都在 `web/src/styles/`、排在 `styles.css` 后面：`composer.css`（输入框、发送键、流光、状态页签）、`chat.css`（消息、步骤行、回合折叠、代码块、改动卡）、`floating.css`（菜单、分段控件、toast、审批卡、右侧面板开合）。`styles.css` 里被它们整条盖掉的旧规则还留着（同选择器、后写的生效）；已经没有任何组件用到的类（`.queue-*`、`.tl-main` 等 11 条）删掉了。
- **发送键**是同一个按钮换 `data-state`（`empty | ready | working | running`，`composer/send-state.ts`），箭头和方块两个字形都在、交叉淡入；`.send.stop`、两个 `aria-label` 和 `data-id="send"` 都没变。
- **流光**：没有用 `@property --ang`，是一个被遮罩成 1.5px 环的元素里转一块锥形渐变（只动 `transform`）。只在 `state === 'running'` 且这个标签在前面时出现；等确认、启动中不出现。
- **状态页签**（原 RunCard）：从输入框上沿后面滑出来；文字变了的时候模糊着换；计时改成 `0:34` 这种钟面（步骤行和摘要里的用时仍写「12 秒」）。停止按钮从 `button.btn.xs.ghost` 改成 `button.rc-stop`。
- **步骤行**：`model/turn.ts` 的 `groupSteps()` 把相邻的同一种已完成步骤合成一行（失败的、等确认的、带子步骤的、还在跑的不合）。行里的动词缩短（「读取文件:」→「读取」）。完成后的用时只在有依据时显示（本页看着它跑完的、agent 报的、transcript 里能定出起点的），所以历史对话里有的行没有用时。
- **只在实时发生时才有进场动画**：`ChatView` 的 `ArrivalCtx`（对话在跑、同一份 items、只是多了东西）；加载历史、重载、换对话、往上翻都不播。回合结束的折叠和数字滚动每个回合只播一次，且要在视野里。
- **流式回答**走的是「逐段」：每次到的那一段包一个 span，320ms 内淡入；一段不再是最后一段、或流结束时还原成纯文本。原来的橙色方块光标去掉了。
- **菜单**：进场从锚点缩放（`placeMenu` 结果里带 `--menu-origin`；侧栏的 `useAnchoredMenu` 用 `spotOrigin()`）；键盘打开的不播。退场是真实指针关闭时原位留一份 inert 副本淡出 120ms（`ui/ghost.ts`），菜单本身照旧立即卸载。不在这次范围里的几个下拉（文件树右键、分组栏预设、标签条 +、图标栏列表、Git 分支菜单）只有外观和进场。
- **`ui/Segmented.tsx`**：带滑块的分段控件（滑块是 `::before`，`seg-math.ts` 算位置）。模型菜单的「智能程度」、设置里的两三选一（改动的显示方式、代理、接口格式、二维码）都用它。
- **toast**：墨色药丸，最多叠三条。位置最后定在**主栏顶上、会话头下面**（不是底部）：底部是输入框、状态页签和审批卡的地方，界面冒烟实测一条报错的 toast 正好压在审批卡的按钮上，点不到。toast 不接收点击，所以文字不能选中复制（以前可以）。没有做「划走」。
- **审批卡**：圆角 24；退场同样是副本（类名 `.pdock-out`，不带 `.pdock`）。一条答完下一条顶上时外壳不重播上移。
- **右侧面板开合**：`.app` 的列宽不再过渡，打开是面板卡片自己滑入；关闭由 `Dock.tsx` 在 React 改 DOM 之前打 `data-rp-closing`，面板淡出 150ms 后列和面板同一帧消失（淡出期间尺寸不变，终端不会被 fit 到别的尺寸）。
- 界面冒烟这一轮 321 项里 5 项不过：3 项是上面 toast 压住按钮（改了位置）；1 项是量审批卡位置时它还在上移动画里（脚本里等它落定再量）；1 项是「紧接着的第二下回车」实际离上一下已经超过 600ms（脚本原来的两段固定等待本来就只剩几十毫秒余量，改成等按钮出现）。另外手机输入行的高度上限从 36 改成 40（发送键 40px）。

### 阶段 3

- 侧栏、首页、设置页、对话框、命令面板、右侧面板、各面板里的框，都是在 `styles.css` 原地改的（没有另起文件）。
- **强调色不再当文字色**：样式表里 20 处 `color: var(--accent)` 改成 `--accent-text`，只留品牌星号两处。徽标里写死的 rgba 换成 `--ok-soft` 等。
- **带描边的框**分三种处理：垫在白卡片上的容器改成一层很淡的底色（`--fill-subtle`，无描边）；容器里的小卡片用阴影环；列表上方的工具条去掉底边线，钉在滚动内容上面的条（文档头、提交框、表头）留线但换成最淡的那档。`styles.css` 里 `1px solid` 从 135 行降到 90 行（其中 4 行是透明边、只占位）——**没有到设计里写的 60 以下**：剩下的大多是表格行、钉住的条、行内徽标的描边和各个旧面板（看板、网关、Android、记忆）里的分隔线，逐个看过后认为留着比去掉清楚。
- 首页列表的页签和自动化页的页签从下划线改成药丸；设置里的页签（MCP · 插件）是同一条轨道。
- 开关 36 × 20，白色圆钮；输入框是淡底色、无描边，焦点环贴着框。
- 右侧面板的四个固定标签放在一条淡色轨道里，选中的是一块浮起的白片（纯 CSS，没有换成 `Segmented`：标签行的宽度判断 `tab-row.ts` 量的是这几个按钮本身）。
- Dracula / Nord / Tokyo Night 的外壳底色原来比卡片亮，改成比卡片暗（和默认深色一致）：`#21222c`、`#272c36`、`#16161e`。
- `corner-shape: superellipse(1.3)`：**启用了**（`styles/corners.css`，排在最后）。Electron 44（Chromium 152）里放大三倍看过：主卡片、输入框的圆角和阴影环都跟着形状走，没有裁剪瑕疵。只给了大面（主卡片、输入框、对话框、命令面板、审批卡的圆角放大 15%；菜单、设置卡片、文件卡只换形状）。
- 浏览器的 `theme-color`、PWA manifest、局域网配对页（`/pair`）换到新底色；iOS 主屏幕的状态栏样式从 `black-translucent` 改成 `default`（原来是白字压在页面上，纸色底上看不见）——没有 iPhone，没验。
- 应用图标（桌面图标、PWA 图标、favicon）**没有动**，还是原来的赤陶色 `#d97757`，和界面里的亮橙不是同一个颜色。
- 减少动态效果时转圈的加载标记仍然转（1.2s 一圈）：停住的转圈读起来像卡死。

### 阶段 4

- 手机的规则在 `styles/phone.css`（头部、输入卡、审批卡、点击区、安全区、断线胶囊）、`styles/phone-sheet.css`（底部抽屉、侧栏抽屉）、`styles/phone-menus.css`（操作单）、`styles/review-phone.css`（审阅）、`styles/extras.css`（排队卡、终端按键条）；都排在桌面规则后面。
- **头部**：会话头在手机上多了 `+N −M` 药丸（以前只有 ☰ · 标题 · ···）。头部直接压在对话上面时（中间没有目标细条 / 已删除提示），下沿是一段渐隐，文字从底下滚过去；别的情况头部就是普通的一行。
- **点击区 ≥ 44px**：用 `::after` 把点击区撑大，图形不变（`:where()` 写的，不抬高优先级：本来就绝对定位的按钮不受影响）。相邻的小按钮（消息下面那排）点击区会互相压一点。
- **底部抽屉**：`store.sheetDetent`（`half` 62% / `full` 92%，不持久化）；`ui/sheet-snap.ts` 是松手落到哪一档的纯函数，`ui/phone-sheet.ts` 是拖动控制器（直接改元素的 `transform`，不走 React）。把手是 `button.sheet-grip`，点一下在两档之间切。内容滚到顶再下拉也能拖；终端、编辑器、横向滚动的 diff、输入框里不触发。`.rpanel` 还是原来那个元素，终端不重挂。
- **侧栏抽屉**：`ui/drawer-gesture.ts`（纯函数）+ `ui/phone-drawer.ts`。因为侧栏关着时本来是卸载的，右滑开始时先把它挂上（`usePhoneDrawer.held`）跟手，松手决定打开才把 `sidebarOpen` 置真。完全打开时没有 `transform`（里面的菜单是 `position: fixed`）。对话行在手机上常显「···」（触屏没有悬停）。
- **操作单**：`ui/ActionSheet.tsx` + `ui/action-sheet.ts`。`Popover`、`useAnchoredMenu`（经 `MenuHost`）、模型菜单、项目菜单在 `store.mobile` 时把原来的菜单根元素原样包进去，portal 到 `<body>`（侧栏抽屉是有 transform 的盒子，会裁掉它）。菜单内容、类名、`data-*` 都没变。是不是操作单在挂载时定，窗口缩放不会中途换。`ui/long-press.ts`：对话行长按 500ms 打开同一张单。
- **系统返回**：`ui/back-layer.ts`。每个打开的层（操作单、底部抽屉、侧栏抽屉）占一条 history 记录，返回手势关最上面那层。历史记录在稍后一步统一对齐，不在中途改：同一个任务里先 `history.back()` 再 `pushState`，Chromium 会把新压的那条丢掉（「账户 → 用量」就是同一次提交里关侧栏、开抽屉）。只在手机宽度的浏览器里启用，桌面版和宽窗口不压记录。
- **触感**：`ui/haptics.ts`，设置 `ui.haptics`（设置 → 外观，默认开）。发送（输入框）、批准（`respondPermission` 且是 allow）、长按出菜单。
- **终端按键条**：`panels/term-keys.ts`（按键 + 粘滞 Ctrl / Alt → 字节，纯函数）。终端根元素外面多了一层 `.term-wrap`，xterm 还是挂在原来的 `.term` 上。打开终端前最多等 1.5 秒让 JetBrains Mono 加载完（xterm 只在打开时量一次字宽）。
- **排队卡**：`chat/QueueCards.tsx` + `queue-card.ts`，在输入框上方、状态条下面；从 `StatusStrip` 里搬出来的。第一张写「已排队，这一轮结束后发送」，后面的写「已排队，排在第 N 条」；超过 3 张折起来。
- **审阅**：`data-lines="wrap|scroll"`（组件状态，手机默认换行）；文件展开后多一行带文字的 暂存 / 还原 / 打开（折着的文件在手机上没有操作按钮，要先点开）；提交区收成「提交 N 个文件」。桌面的 DOM 不变。
- **手机壳**（`web/src/shell/shell.css`）：同一套颜色（抄了十几个原色，跟系统深浅色），不带字体；压缩后 4.3 KB → 7.4 KB，整个壳约 93 KB。
- **步骤详情**：手机上点对话里的一步，详情在抽屉里打开（`ToolHead` 在 `store.mobile` 时走 `inspect`，和桌面的「详情」按钮同一条路），对话不被撑开。合并行（读取 ×3）仍是原地展开出各步，再点其中一步进抽屉。
- **没改的**：输入框回车在手机上仍然是发送（软键盘的回车键标成「发送」），没有改成换行。
- **收尾时改的：系统按钮的高度跟着它下面那一行走**（Windows / Linux）。整套做完后在带真实系统按钮的窗口里截图看（`titleBarStyle: 'hidden'` + 透明 overlay，`desktopCapturer` 只截自己）：按钮没和面板的「+ ×」重叠（后者右边到 1134，按钮从 1146 开始），但固定 40px 高的按钮区域让 − □ × 的中心在 y=20，而卡片头部行的图标在 y=34，高出 14px。现在按钮区域的高度 = 上面的缝 + 那一行的高度（`tab-row.ts` 的 `captionRow()` / `captionHeight()`：头部行 8 + 52 = 60，工作台工具下的分组栏 / 标签条 8 + 40 = 48，紧凑密度 56 / 44，Linux 没有上边的缝所以是 52 / 40），由页面随颜色一起报给壳（`setTitleBarColors` 的第四个参数，`desktop/src/main.ts` 夹在 32–80 之间，新窗口先用 60）。这样图形只比那一行的图标高半个缝（4px），而且按钮区域**不伸到那一行下面**——只有那一行自己要让出右边 142px，下面的东西不用管。试过 68（完全对齐）：区域会压到下一行顶上 8px，面板正文顶部的标题行 ×、分组栏下面的标签条都在那里，点偏一点就成了关窗口，所以没用。跟着改的三处：挪到按钮下面的标签行（`.stacked`）、收成图标栏的面板、设置页顶上的拖动条，上边距 / 高度从 40px 改成 `--h-head`。另外图片查看器的工具栏以前右边几个按钮压在系统按钮下面（改版前就是这样），现在让出 150px（mac 左边让 84px）。四种情况各截了一张（右侧面板、1024 宽挪到下面、设置页、工作台工具 + 分组栏），并数了伸进按钮区域的可点元素：都是 0。页面把高度报给壳的那一步也在真的桌面壳里验了：`electron .` 起 `desktop/dist/main.js`，家目录、数据目录、`--user-data-dir` 都指到临时目录（不碰正在用的那个；当时桌面上确实还开着另一个 Claude Web 窗口，按窗口尺寸区分），从外面截它的窗口、量最小化那一横所在的行：默认界面（首页顶行）中心约在 y=30，`ui.workbench` 打开（分组栏，只有页面报过去才会是 48）约在 y=24，相差的 6px 和算的一致。Linux 的 52 / 40 没验。
- **没法验的**（没有真机）：iOS / Android 上的触摸仲裁（`touch-action`、下拉时第一下 `touchmove` 的 `preventDefault`）、软键盘弹起时抽屉和操作单的高度、安全区、长按后会不会多触发一次点击、系统边缘返回手势和右滑开侧栏会不会打架、震动、iOS 主屏幕的状态栏。这些都只用合成事件或桌面 Chromium 的手机宽度看过。
