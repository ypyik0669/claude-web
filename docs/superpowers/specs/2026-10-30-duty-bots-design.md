# 值班 Bot：住在你电脑里的常驻队友（2026-10-30）

> 来源：10-28 的对话 `c87dc48c`（Grok Bot / dots / Muse / Cue / Duet 调研，报告在 `reports/AI 队友 Bot 玩法全景.md`）和本轮设计讨论。
> 目标：比上一版的「六条极限设计」更进一步——解决调研里挖出的全部 28 个问题，Bot 默认权限宽、能自己探索、越做越多，用户只需要看着它；不设产品级边界，所有上限都是用户的旋钮。

## 0. 要解决的问题

调研里的问题归成六堆，这份设计每一堆都要有对应的机制：

| 堆 | 问题 | 本设计的对应 |
| --- | --- | --- |
| 做不完 | 长任务完整成功率约 21%；Bot 自报「做完了」≠ 真做完；页面改版后照旧点老位置 | §3 检查点续跑、程序 / 模型双验收、「说的 / 核实的」分栏；§4 脚本固化与自愈 |
| 出事 | 「永久允许」泄露住址；安全指令被上下文压缩丢掉后批量删邮件、喊停停不下；多 Bot 共享凭据；邮件提示注入；Bot 胡乱解释自己 | §5 闸门在 `canUseTool` 层、带范围的升档、双模型隔离、Rule of Two、每 Bot 独立 profile 与保险库、带外硬停止、审计即事实 |
| 烧钱 | 5 分钟轮询每月约 $400；每次重读整段历史；额度去哪了看不见 | §3 零成本预检、每次新对话、默认慢节奏；§7 负载条、按 Bot / Routine 的账本、预算 |
| 不好用 | 忘了用；审批 10 分钟过期；每件事新建任务越堆越多；夜里卡住等人 | §6 唯一收件箱（不过期、批量批、推到 IM / 手机）、总管 Bot、勿扰时段；§3 草稿队列不阻塞 |
| 环境 | 机房 IP 被封；掉登录；容器重启丢环境；验证码没人接 | 本机执行、已登录的 ego lite；§8 接管、跟着你走、一次性沙箱 |
| 合规 | 订阅条款灰区；平台封号 | §5 默认走 API / 网关路由组；§10 风险说明而非硬拒 |

## 1. 总体架构

新建独立子系统 `server/src/bots/`，现有模块当积木，不改它们的形状：

```
bots/
  store.ts        Bot 档案的读写（~/.claude-web/bots/<id>/）
  scheduler.ts    Routine 调度（定时 / 事件 / 手动 / 转派；复用 schedules/cron.ts 与 catch-up.ts）
  pipeline.ts     一次运行的流水线（预检 → 开对话 → 执行 → 验收 → 收尾）
  policy/         策略引擎：动作归类 classify.ts、四档与范围 rules.ts、信任升降 trust.ts、Rule of Two
  audit.ts        审计记录（每个工具调用一行）
  inbox.ts        收件箱（待批 / 发现 / 草稿 / 提议）
  skills.ts       固化脚本：匹配、影子对比、转正、回退
  explore.ts      探索 Routine
  verify.ts       验收：程序检查 + 换厂商模型核对
  events/         事件源：git / 文件 / IM / webhook / 网页差异 / IMAP / ICS
  vault.ts        保险库（按 Bot × 域名）
  service.ts      对外接口，接协议
```

复用关系：起对话 `pool.open()`；闸门挂在 `session-runner.ts` 的 `onCanUseTool()`；记账 `usage/ledger.ts`；记忆 `memory/service.ts` 新 scope；IM `im/router.ts`；联邦 `federation/rewrite.ts`；浏览器 `web/ego.ts`；网吧角色当头像。现有定时任务页保留，旁边加「升级成 Bot」。

前端：图标栏新分区 `bots`（`web/src/features/bots/`，分区页不卸载）；收件箱挂在总览栏 `MissionPanel` 的「需要你」lane 上扩开。

协议（`server/src/protocol.ts`）：请求 `bots.list / bots.get / bots.create / bots.update / bots.delete / bots.pause / bots.resume / bots.runNow / bots.stopAll / bots.inbox.list / bots.inbox.answer / bots.runs.list / bots.runs.get / bots.generate（一句话 → 草案）/ bots.templates / bots.vault.set / bots.takeover.done`；事件 `bots.changed / bots.run / bots.inbox / bots.load`。带 sessionId 的请求进联邦路由表；`bots.*` 按 Bot 所在节点转发。

## 2. Bot 是什么

一个 Bot 是一个目录 `~/.claude-web/bots/<id>/`（跟着机器走，不进 meta.json）：

- `bot.json`：名字、头像（网吧角色 id）、**章程**（一句话职责、服务对象、认可的数据源、报告格式、完成条件）、工作目录、模型档位（省钱 / 均衡 / 最强，映射到路由策略，各工序可逐槽改）、策略（§5）、预算（日 / 周上限，探索占比默认 20%）、Routine 列表、事件订阅、输出去向（对话 / IM 频道 / 文件 / 收件箱）、在哪跑（本机 / 联邦节点 / 跟着我走）、浏览器身份（独立 / 共享主 profile）、勿扰时段与通知阈值、Routine 上限（默认 20）。
- `state/<routineId>.json`：Routine 之间传递的状态与检查点。
- `skills/<name>/`：固化脚本 + 适用条件 + 预期结果形状 + 历史版本。
- `runs/<runId>.jsonl`：运行记录与审计，全量保留，可导出。
- `profile/`：这个 Bot 的 ego lite Space / 内置浏览器 partition。
- `installed/`：Bot 自己装的工具（MCP、CLI、npm 包）。

记忆：memory.db 增加 `scope: 'bot'`、`key: botId`；每条可查看、可删。用户对 Bot 的纠正（拒绝、回滚、「以后别这样」）自动写入 bot 记忆，并触发信任降档（§5）。

**创建三入口**，都落到同一份 bot.json：

1. 一句话：输入自然语言，`bots.generate` 用最强档模型生成章程、Routine、预检脚本草案、验收条件、策略、预算，一屏预览全部可改。
2. 模板：内置 14 类（晨报、PR 巡检、收件箱分拣、监控情报、省钱账单、购物比价、销售客服、工程调度、遗留 RPA、内容创作、家庭生活、求职、金融持仓、多 Bot 团队），每个带中英文章程和默认护栏；有封号先例的（微信、小红书、闲鱼）照样提供，卡片上写明风险。
3. 从对话 / 录屏生成：普通对话里做完一件事点「存成 Bot」；或录屏（现有录屏抽关键帧）生成六段式流程（输入 / 步骤 / 决策规则 / 审批点 / 错误处理 / 完成标准）。

保存时可以「保存并先跑一次」：一期是真跑一次（结果进收件箱）；只输出「我本来会做什么」的影子模式放到二期。

**总管 Bot**：内置、不可删、不干具体活。接用户在 IM / 手机上随口说的事，转派给合适的 Bot 或提议新建一个；多个 Bot 要做同一件事时加锁去重；有「全部停」。

## 3. 一次 Routine 运行

```
触发 → 预检 → 开新对话 → [匹配脚本 → 跑脚本 | 唤醒模型] → 检查点 → 验收 → 收尾
```

1. **触发**：定时（cron / 间隔，最短 1 分钟）、事件（§8）、手动、总管转派。错过的按现有 7 天补跑规则补最近一次；探索 Routine 不补。
2. **预检**：可选脚本（shell / Node / ego lite），输出指纹。指纹与上次相同 → 记一条「无变化，跳过」，不开对话。没有预检的 Routine 在界面标「每次都会唤醒模型」并显示月成本估算。
3. **开对话**：每次运行 `pool.open()` 一个新对话，id 前缀 `bot_<botId>_<runId>`。注入：章程、Routine 指令、这条 Routine 的状态文件、bot 记忆里相关几条、工具白名单、策略摘要（只是告知，闸门不靠它）。对话在对话库里归到 Bot 名下，可随时查看、插话。
4. **脚本优先**：在 `skills/` 里按适用条件匹配。命中 → 跑脚本，结果符合预期形状即完成，不叫模型；不符合（页面改版、掉登录、返回空）→ 唤醒模型，附脚本、报错、截图，模型修好后存新版（旧版保留可回退）。无脚本 → 模型做；成功后自动提炼成脚本草案，标「未验证」，下次运行先影子模式与模型并行跑一遍，结果一致才转正。
5. **检查点**：长任务按步骤写入状态文件。超时（默认 30 分钟，可配）或出错 → 下次从检查点续。
6. **验收**：每条 Routine 必须有完成条件。程序可查的（文件、PR 状态、行数、HTTP）跑脚本；需判断的交给另一家厂商的模型、只读无工具核对。状态阶梯：尝试过 → 已发出 → 对方确认 → 已核实。运行记录里「Bot 说的」与「核实到的」分两栏。不过 → 按 Routine 策略：升一档模型重跑 / 从检查点续 / 放收件箱；连续失败 N 次（默认 3）停用该 Routine 并通知。
7. **收尾**：写状态、写运行记录（费用、工具调用数、改动文件、发出的消息、验收结果）、按输出去向投递、释放 worktree。

遇到「先问我」的动作：写进收件箱**不阻塞**，Bot 继续做别的；批了之后从检查点续。

## 4. 自主探索：自己找活、自己长本事

每个 Bot 内置一条**探索 Routine**（默认每天一次；省钱档每周、最强档每小时），做四件事：

1. **看环境**：在章程认可的数据源内转一圈——工作目录 git 日志、issue / PR、绑定的 IM 频道、自己的运行记录与失败、memory.db 的项目 / 全局记忆、用户最近对话的摘要（只读）。回答「我管的这块，有什么没人管的、重复的、要坏的」。
2. **分流**：每件事按 §5 的动作类别和信任档：只读的直接做，结果进收件箱「发现」；要动手的看信任，够就做了告知，不够就起草进「草稿」。
3. **长本事**：反复出现的事 → 新 Routine 草案（先影子跑 3 次，用户转正；连续转正几条后提议「这类以后直接转正」）；成功路径 → 脚本（§3.4）；缺工具 → 去 skills / MCP / 插件市场 / npm 找，能自己装的装进 `installed/`（动作类别「装东西」默认「做了告诉我」），装不了的列进「提议」。
4. **自我复盘**：读运行记录和用户纠正，改记忆与脚本；验收常不过的 Routine 自己调指令或升模型档；三次仍不过标「需要你」。

边界由程序定：探索只在章程数据源和目录内；独立预算（默认占 Bot 预算 20%）；Routine 上限（默认 20，超了先清旧的）；所有自建 Routine / 脚本 / 记忆 / 安装的工具带「自建」标记，界面单独一栏，一键停、删、回滚到用户上次看过的状态。总管 Bot 额外可提议新建 Bot。

## 5. 策略：宽但不出事，闸在程序层

**原则**：Bot 能做的多，「不能做」由 `onCanUseTool()` 里的策略引擎判定，模型看不到也改不了，上下文压缩不影响。

**动作归类**（`policy/classify.ts`，纯函数：工具名 + 参数模式 → 类别）：读 / 写本地 / 操作浏览器与电脑 / 对外发送 / 付款交易 / 不可恢复删除 / 装东西与改系统。规则表举例：`git push`、HTTP POST 到非本地域名、IM send → 对外；`rm -rf`、删远端分支、删邮件 → 不可恢复删除；已知支付域名、含金额的表单提交 → 付款。归不出的按「对外」处理。

**四档 + 范围**：每类别在每个 Bot 上是「直接做 / 做了告诉我 / 先问我 / 禁止」之一。**默认**：读、写本地、浏览器与电脑、命令 → 直接做；装东西 → 做了告诉我；对外发送、付款交易、不可恢复删除 → 先问我。没有「禁止」的默认项。升档必须带范围：收件人 / 域名 / 频道 / 金额上限 / 每日次数 / 有效期；范围可以选「无限制」（§10）。

**信任是挣来的**（`policy/trust.ts`）：同类别同范围连续批准 N 次（默认 3）无纠正 → 提议升档，用户点一下生效；一次纠正（拒绝、回滚、验收不过）→ 自动降回「先问我」。Bot 页显示信任图。

**全自动档**：按 Bot 单独开，开时填金额上限、白名单、每日动作上限、有效期（都可选「无限制」）；Bot 名旁挂标记；到期自动关。无全局总开关，但有「放开全部」（§10）。

**不可信内容隔离**：邮件、网页正文、他人 IM 消息、PR 评论不直接进主对话。隔离读取器（最便宜档模型、零工具）读成结构化摘要，字段带「不可信」标签。带标签数据流向对外发送 / 付款时，无论档位强制「先问我」。Rule of Two：一次运行最多同时具备「读不可信输入 / 碰敏感数据 / 对外改状态」两项，第三项降为先问——可在 §10 关闭。

**凭据不进对话**：保险库按 Bot × 域名存 token / 密码 / 一次性卡号；由程序注入浏览器或请求头，模型只见「已登录」；审计记「用了 <域名> 凭据」。登录、验证码、2FA、支付确认一律接管（§8）。

**硬停止**：停止按钮、IM `/stop`、手机停止、总管「全部停」走现有 `interrupt()`：先拒待审再杀进程。永远有效（§10 不可关）。

**快照与撤回**：运行前 worktree / stash 快照；对外动作在审计里记「怎么撤」，能撤的提供按钮，不能撤的在审批卡上红字「不可撤」。高风险环境动作进一次性 worktree 或 Docker（§8）。

**对外署名**：默认带「由 <Bot 名> 代发」，按 Bot 关。

**审计**（`audit.ts`）：每个工具调用一行——时间、类别、档位、判定依据（规则 / 信任 / 用户批 / 全自动）、输入摘要、结果、可否撤。运行记录展示的「Bot 做了什么」来自审计，不来自 Bot 自述。永远写入（§10 不可关）。

## 6. 入口与界面

**Bot 分区页**三栏：左 Bot 列表（总管置顶；头像、一句话职责、状态 空闲 / 在跑 / 排队 / 暂停 / 需要你、今日花费、信任小图）；中 详情（章程、Routine 表、自建栏、运行记录、脚本、记忆、策略与信任图、预算、保险库、在哪跑）；右 正在跑的对话（复用对话视图，可插话）。顶部**负载条**：在跑 / 排队 / 今日花费 / 本周估算 / 全部停。

**收件箱**（总览栏「需要你」lane 扩开）四类：待批（批 / 批并升档带范围 / 拒 / 看对话，多选批量）、发现、草稿（点「发」走对外动作）、提议（Routine 转正、升档、新 Bot、装工具，一键采纳）。待批不过期。每条标 Bot、运行、可否撤。

**手机与 IM**看同一个收件箱：手机壳 Bot 分区以收件箱优先；IM 网关加 Bot 频道绑定，推送发现 / 草稿 / 待批，inline 按钮扩成带范围的升档选项；频道里 @ 即下指令。勿扰时段夜间只攒不推，早上一条汇总；低于阈值的发现只进收件箱。

**创建流程**：新建 → 三入口 → 一屏预览 → 保存（或「保存并先跑一次」；影子模式在二期）。首次打开 Bot 页：「从这三个开始」（晨报、PR 巡检、收件箱分拣）。

**运行记录页**：时间线，每行 触发源 / 跳过或跑了 / 脚本或模型 / 费用 / 验收 / 「说的 vs 核实的」；按 Bot、Routine、日期筛；可导出。

**设置 → Bot**：全局并发上限（默认 2）、全局预算、值班模式、默认模型档位、Bot 默认供应商（默认 API / 网关路由组，写明不默认用 Claude 订阅登录的原因）、「放开全部」。

与现有页面：自动化页定时任务保留 + 「升级成 Bot」；后台页照常显示 Bot 派出的子代理；网吧里每个 Bot 是一个角色，在跑时有动作。

## 7. 值班模式与负载

要有一个 claude-web 进程在跑 Bot 才会动。值班模式三档：桌面版关窗口缩到托盘继续跑（新行为，关窗口不退出）+ 开机自启可选；服务端注册成 Windows 服务 / macOS launchd / Linux systemd，无界面值班，手机经「在外面也能连」看收件箱；放到联邦常开节点（§8）。

空闲时只有 30 秒一次的调度检查，零模型进程。负载控制默认开：预检挡前面；全局并发上限 2；新 Routine 默认每小时或每天，探索默认每天；5 分钟以下频率在界面提示月成本；每 Bot 日 / 周预算 + 全局预算，超了不开对话。所有 Bot 的网关调用带 `botId`、`routineId` 标签，账本按 Bot / Routine 出费用。

## 8. 执行环境

**每 Bot 一套浏览器身份**：ego lite 独立 Space（`profile/`），内置浏览器独立 session partition；Cookie、登录态、下载目录分开。可显式选共享用户主 profile（总管、只读 Bot 常用），默认分开。

**接管**：登录页、验证码、2FA、支付确认 → 收件箱 + IM 一条「需要你接管」；桌面把浏览器窗口提前；手机经现有 WebRTC 通道推画面。接管期间 Bot 工具调用暂停，审计记「人工接管」段，完成后 `bots.takeover.done` 从检查点续。

**跟着我走**：Bot「在哪跑」选「跟着我走」时，本机在线则本机跑；本机睡眠或退出值班时把 `state/`、`skills/`、bot.json 同步到指定常开节点继续；回来再接回。浏览器 profile 不跨机器搬，远端用远端的 profile，需登录走接管。底下复用联邦 `session.open` 转发与 id 前缀；bot.json 走现有同步（WebDAV / S3 / GitHub）或联邦直连。

**一次性沙箱**：章程外的陌生网站、装陌生依赖、跑陌生仓库命令 → 一次性 worktree；装了 Docker 的机器可选容器（`sandbox.json` 定镜像与挂载），跑完销毁只拷回产物。

**指挥工程 agent**：工具白名单可带 sessions MCP。发现 bug → 开 worktree 对话让 Claude Code / Codex（按路由组）修 → 盯 CI → PR 进「草稿」→ 合并后验收。Bot 不自己写代码。

**事件源**（`events/`）：git / PR / CI（vcs 服务）、文件变化（watchTree）、IM 频道消息（网关）、webhook（`/hooks/<botId>/<token>`）、网页差异（ego lite 定时抓块比哈希）、邮件（IMAP IDLE；各家 OAuth 不内置，Bot 可自己装对应 MCP）、日历（ICS）。事件内容一律过隔离读取器。

**模型分层**：档位映射到 `smart-free / smart-auto / smart-performance`，工序为槽：预检无模型；隔离读取最便宜；规划决策最强；浏览器执行中档；验收换厂商；固化脚本无模型。便宜档失败或验收不过自动升一档重跑一次。

## 9. 无边界：能力不设上限，Bot 自己扩

Bot 的能力集 = claude-web 已有的一切（Claude Code、Codex 等 agent、ego lite、内置浏览器、computer MCP、IM、联邦、记忆、录屏、sessions MCP）+ **它自己装的一切**。缺工具时自己找、装、写接入脚本、存成技能，装完在收件箱告知。产品只保证：装的东西进 `installed/`，凭据进保险库、登录走接管。云电脑（E2B / Daytona）、邮箱 OAuth、打电话、购物等服务不预先接好，但 Bot 走到那一步就能自己接。

## 10. 旋钮：所有限制都是用户的

产品不硬拒任何事。每道闸都有「关掉」，关时弹一次具体风险说明（例：「它可以在你不在时无上限花钱」「Anthropic 条款自 2026-04 起可能禁止用订阅这样跑，有封号风险」），确认即生效。包括：升档范围选「无限制」；全自动档填「无限制」；交易类从「先问我」升到「直接做」；关 Rule of Two；关隔离读取器；用 Claude 订阅登录跑 Bot；关对外署名。Bot 页右上「放开全部」一次拧到底，Bot 名旁挂「无闸」标记。

**只有两样不能关**：硬停止、审计写入。它们不限制 Bot，是用户「看着它」的前提。

默认值始终是「宽但不出事」；想无边界的用户一路点「好」或直接「放开全部」。

## 11. 分期

三期连续做，每期末整体审查 + verification 验收 + 一轮修正；三期全部完成再发版。

- **一期 能值班**：`bots/` 子系统（store、scheduler、pipeline：预检 → 新对话 → 检查点 → 程序验收 → 记录）；策略引擎接 `canUseTool`（归类、四档 + 范围、信任升降、审计、硬停止）；收件箱四类；Bot 页、创建三入口（录屏入口三期）、14 模板、负载条；memory bot scope；账本按 Bot；值班模式三档；IM 频道绑定 + 勿扰；并发与预算；旋钮与「放开全部」。验收：新用户一句话建晨报 Bot，每天自己跑、只出草稿、费用可见。
- **二期 能自己变强**：脚本固化与自愈（最先做）；双模型隔离 + 打标 + Rule of Two（其次）；模型验收与「说的 / 核实的」；探索 Routine 与自建栏；自装工具；全自动档；快照与撤回；每 Bot 独立 profile + 保险库 + 桌面接管。
- **三期 能到处跑、能指挥**：事件源全套；跟着我走；手机接管画面；Docker 沙箱；指挥工程 agent；总管提议新 Bot；从录屏生成；模板中英文全套；官网与 README。

## 12. 测试

- 纯函数单测：归类、四档与范围、信任升降、Rule of Two、预检指纹比对、检查点续跑、脚本匹配与预期形状、收件箱分类、cron 调度。
- 流水线：用 `session-runner.test.ts` 那套假 SDK 跑完整一次运行（预检跳过 / 唤醒模型 / 先问我不阻塞 / 验收不过重试 / 硬停止杀进程）。
- e2e 新阶段：临时 HOME 建一个 Bot，手动触发，收件箱出现草稿、审计有记录、账本有费用、停止生效、「放开全部」后待批为空。
- ui-smoke：Bot 页、收件箱、创建流程，任何 console 错误即失败。
- i18n：所有新字走 `tr()`，`extract.mjs --check`；wording 闸（不出现 会话 / 引擎 等词）。
- 真机：真 Key 在两个中转上跑一个真 Bot 一整天，报跑了几次 / 跳过几次 / 花费 / 验收通过率。
- 每期审查点名：闸门、隔离读取器、保险库注入、硬停止。

## 13. 风险

脚本固化与隔离读取器工作量最大、最易做成半吊子，二期放最前。探索的「越做越多」靠影子模式和自建栏兜底，否则用户第一个月就会关掉。ego lite 独立 Space 需要确认 ego-browser 支持多 profile；不支持则先用内置浏览器 partition 隔离，ego lite 退回共享并在界面标明。值班模式的托盘常驻会改桌面版「关窗口即退出」的现有行为，要在设置里可关。
