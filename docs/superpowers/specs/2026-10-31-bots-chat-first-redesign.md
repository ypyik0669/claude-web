# 值班 Bot 重构：聊天优先（Grok Bot 式）

2026-10-31。起因：用户试了一期的安装包，说「完全不是一个东西」——一期做成了管理后台（列表 → 表单详情页 → 单独的收件箱 → 模板库），他要的是 Grok Bot / Muse / Hermes 那种「每个 Bot 是一个联系人，你和它聊天」。调研：`research_notes/bot-uiux/`（grok_bot_ui / muse_dots_ui / hermes_and_oss_ui / others_ui，每篇末尾有「可直接借鉴」清单）。

一期的服务端（策略闸、例行、预检、批准后续跑、预算、审计、值班服务、单服务器锁）全部保留；这次换的是**界面和交互模型**，服务端加「Bot 自己的对话」和「Bot 管自己的工具」。

## 1. 三栏工作台

```
┌ Bot 名册 ───────────┬ 和「晨报」的对话 ─────────────────┬ 晨报 ▸ 资料 ───────────┐
│ 🔍 搜索        ＋    │ (头像) 晨报  · 📰 正在读 6 封邮件…  │ (大头像) 晨报           │
│ ● 需要你 (2)         │                                   │ 每天的一页纸 · 改名      │
│ (头)晨报   需要你 9:41│  ─ 已创建例行 ⏲ 早间简报 ─          │ ─ 电脑 ─────────────── │
│   3 份草稿等你点头    │ 晨报：搞定了。紧急 2 / 等你 1 …    │ [实时画面缩略图]         │
│ (头)PR巡检  在干  9:30│ ┌ 例行 · 早间简报 · 用时 46 s ┐     │ Live · 晨报在操作 ｜接管 │
│   CI 挂了，在查原因    │ │ 6 份草稿待你看          打开 │     │ ─ 例行 ─────────────── │
│ (头)收件箱  —   昨天  │ └──────────────────────────┘     │ ● 早间简报 工作日 8:00 ⏸│
│ ── 群 ──             │ ┌ 发出去 · 晨报想要 发邮件给 …  ┐     │ ○ 周报     周五 18:00  │
│ (叠头)周会群          │ │ 收件人 / 标题 / 正文全文       │     │ ＋ 在对话里说一句就能加 │
│                      │ │ [拒绝]      [允许 ▾]          │     │ ─ 权限 · 记忆 · 用量 ── │
│ 总管 ★               │ └──────────────────────────┘     │ 本周 $3.10 / 预算 $12   │
│                      │ [ 跟晨报说点什么…           🎤 ] │                         │
└──────────────────────┴───────────────────────────────────┴─────────────────────────┘
```

- **左：Bot 名册**（替换现在 Bot 分区的侧栏 + 列表页）。每行：头像 34px｜粗体名字 + 灰色职位｜第二行最后一句话（同事口吻：「3 份草稿等你点头」）｜右侧时间｜状态：需要你（琥珀点 + 计数）/ 有新结果（蓝点）/ 在干（头像动起来）。「需要你」的置顶一组；总管带 ★；群在下面一组；可置顶、隐藏（折叠到底部，例行照跑，不通知）。只有一个 Bot 时不显示空名册，直接进它的对话（OpenClaw 的做法）。
- **中：和这个 Bot 的对话**（复用现有 ChatView：工具卡折叠、Markdown、提问卡、权限卡、输入框）。顶部：头像 + 名字 + 一句进行时状态（「📰 正在读 6 封邮件…」，闲着写「在线」，出错写原因和下一步）。时间线里除了普通消息，还有：
  - **系统事件**（居中小灰字，可点开）：「已创建例行 ⏲ 早间简报」「已改名为 晨报」「已记住：周报发给张三」「和 PR巡检 的 4 条消息」。
  - **例行运行卡**：「例行 · 早间简报 · 用时 46 s · 一句结论」＋「打开」（跳到那次运行的完整对话）；运行中显示当前步骤。
  - **批准卡**（取代单独的收件箱页）：第一句「〈类别〉· 晨报想要 〈做什么〉」，灰字「请核对后再批准」，证据区（命令 / 收件人和正文 / diff / URL 全文，密钥打码），要点行（金额 / 影响范围），等宽的「拒绝｜允许 ▾」，▾ 里是「仅这次 / 这次运行内 / 对这个目标总是允许 / 总是」（默认最窄）。处理完留「已允许 · 9:42 / 已拒绝 / 已过期（以后总是允许？）」。一张卡没批，Bot 先做别的（一期的「拒绝并排队」语义不变）。
  - **草稿卡**：「发送 / 丢弃 / 以后不用草稿」。**提议卡**：「要不要我以后每天做？A 每天 9 点 / B 每周一 / C 不用」（用现有的提问卡）。
  - 输入框上方几个常用 chip：「今天怎么样」「跑一次例行」「看待批」。
- **右：Bot 资料栏**（点顶栏名字或头像打开，不卸载只 hidden，记住上次停在哪一节）：资料（头像、名字、职位、通知开关）→ **电脑**（实时缩略图 + 谁在控制 + 接管 / 交还；没在用时「电脑闲着」）→ **例行**（人话时间、状态点、暂停开关；点开看指令、下次运行、运行历史，按钮 暂停 / 测试 / 编辑 / 删除；「编辑」往输入框预填「改一下例行：早间简报」）→ **权限**（每类一行四档：直接做 / 做了告诉我 / 先问我 / 不许；下面是「总是允许」过的规则，带来源卡片和时间，可撤销）→ **记忆**（这个 Bot 的记忆条目，可改可删，「这条不对」）→ **文件**（它产出的东西，按日期）→ **用量**（本周 / 预算、上下文小环）。
- **顶部横幅**：别的 Bot 有待批时，对话上方一条「2 件事等你批 · 查看」。总览 →「需要你」照旧列出所有待批（一期的入口不删）。

## 2. 新建 Bot = 一个小页面 + 一段对话

1. 名册 ＋ →「新 Bot」页：头像（形状 × 颜色，或网吧的像素角色）、名字、「开始」；下面是模板建议卡（晨报 / PR 巡检 / 收件箱分拣 …，点一下就是用它开场）。
2. 进入对话，**Bot 先开口**（服务端发一条隐藏的 kickoff，模型自我介绍）：「嗨，我是 晨报。我会在你不在的时候接着干活。你最想让我帮什么？」接着一张字母选项卡（现有 AskUserQuestion 卡）：A 每天早上给我一页纸 / B 盯一个仓库的 PR 和 CI / C 整理收件箱 / D 盯价格或消息 / E 帮我写东西 / F 其它（自己写）。
3. 聊几句后 Bot **自己**用工具定下：职位、职责（章程）、第一条例行（回一张确认卡：查什么 / 什么时候 / 什么情况通知 / 结果发到哪；必须有结束日期或明确写「一直」）。时间线里出现对应的系统事件。
4. 最后一张「规矩」卡：默认权限（发出去 / 付钱 / 删除先问我）＋ 可改；确认后写进策略（**策略只能由人通过卡片改，Bot 只能提议**）。
- 选了模板 = 跳过 2 的提问，Bot 直接按模板说「我按『PR 巡检』来，先确认两件事：哪个仓库？CI 挂了要不要叫你？」
- 一期的「一句话生成」对话框删掉（它背后的生成对话还漏进了用户的对话列表，截图里看到的那条）。

## 3. 服务端要加的

- **每个 Bot 一个主对话**：`bot.threadId` = 一个 gated 的 Claude 对话（走一期的闸，Bot 的默认来源）；你在名册里点它就是打开这个对话。主对话不进普通对话列表（标 `botId`，库里按 Bot 归档；生成 / kickoff 这类内部对话也一样不出现）。
- **Bot 管自己的工具**（进程内 MCP，像 sessions MCP）：`bot_profile`（改名 / 职位 / 头像）、`routine_create / update / pause / delete / test`、`remember`（写 bot 记忆）、`propose_policy`（只能出一张卡，人点了才生效）、`ask_bot`（@另一个 Bot，第二批）。这些工具不经「发出去」分级，但都记审计、都在时间线里出系统事件；策略和预算 Bot 改不了（一期的 self-guard 照旧）。
- **Bot 时间线**：`bots/<id>/timeline.jsonl`（系统事件、运行卡、批准卡、草稿卡的引用）。前端把主对话的消息和时间线按时间合起来画。模型那边：你下一次发消息时，自上次以来的事件（例行结果、批准结果）作为隐藏的 `<cw-bot-events>` 附在消息前面，让它知道。
- **例行运行**还是各开一个对话（一期不变，「打开」能看完整过程），结束后往时间线写一张运行卡 + 一句结论，主对话名册行更新「最后一句」。
- **状态**：在干 / 需要你 / 有新结果 / 出错（含原因：预算用完 · 明早 0 点恢复、来源没有这个模型、电脑睡着了），推给名册和顶栏。
- **电脑**：Bot 用内置浏览器 / 操控电脑时，它的画面在资料栏里实时显示（复用 browser_screenshot / computer MCP 的截图通道，每 4 s 一张，失败 3 次标「上次看到 · 时间」）；接管 = 暂停这个 Bot 的运行并把浏览器标签交给你，「交还」继续。
- 一期的 `bots.inbox.*` 数据保留；批准卡就是 inbox 的 approval 画在对应 Bot 的时间线里。

## 4. 头像

- 默认：按名字生成「形状 + 颜色 + 两只眼睛」的 SVG（约 12 形状 × 10 颜色），名字一样脸就一样；可锁定、换一个。
- 头像就是状态灯：闲着慢慢眨眼；在干时左右看 + 三个小点；等你时琥珀色描边；出错灰掉。系统「减少动态效果」时静止。
- 可选：网吧的像素角色（`server/src/characters/`）当头像，带打字 / 闲着两种帧。

## 5. 群（第二批）

名册 ＋ → 建群：选 2–6 个 Bot、起名，群头像两个叠在一起。群里 @谁谁回，没 @ 就由总管（或第一个）分工；Bot 之间接话有轮数上限（显示「本轮已接 2 / 3」），一整轮没人说话就停；1:1 对话里 Bot 和别的 Bot 来回的消息折叠成一行。一期的「总管」在这里真正干活（转派）。

## 6. 手机

名册：顶部一排置顶的 Bot 头像，下面是列表（同桌面的行）。点进去是对话（批准卡、运行卡同样内联），右上角头像 → 资料（同右栏，分节变成整页）。「需要你」超过 3 分钟电脑上没处理才推送（IM / 手机通知），桌面正看着时手机不响。

## 7. 分批

- **A 批（这次）**：名册、Bot 主对话（复用 ChatView）、时间线（系统事件 / 运行卡 / 批准卡 / 草稿卡）、对话式新建（新 Bot 页 + kickoff + 提问卡 + Bot 管自己的工具）、资料栏（资料 / 例行 / 权限 / 记忆 / 用量；电脑先做「最近画面」）、头像 SVG + 状态动效、手机名册和对话、修掉生成对话漏进列表。删掉一期的详情表单页、单独收件箱页、一句话生成对话框（设置里「值班 Bot」那块保留）。
- **B 批**：群聊 + @ + 总管转派、电脑实时画面与接管、像素角色头像、提议卡「以后每天做？」的自动触发、输入框上方 chip。
- 不变：策略闸、分级、预算、值班服务、单服务器锁、e2e 第 42 阶段的服务端断言（UI 那段重写）。

## 8. 验收

- 像截图那样：名册里每个 Bot 有头像、最后一句、时间、状态；点进去是聊天；新建时 Bot 先开口并给 A–F 选项；说一句「每个工作日 8 点给我晨报」，右栏例行里出现一条并能暂停；批准卡在聊天里点「允许」后，那次运行接着跑。
- ui-smoke 新一段：名册行、对话里的批准卡 / 运行卡、新建流程到提问卡、资料栏五节；e2e 加：kickoff → 提问 → `routine_create` → 例行出现在 `bots.get` 里。
- 真机：用一个中转建一个 Bot、走完对话式新建、跑一次例行、批一张卡，截图给用户。
